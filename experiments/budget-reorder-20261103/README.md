## Budget and locality axis

Full, M=2 and M=0 are tested with TXY, T|XY and T|X|Y in original and Starling order. M=2 uses greedy smallest-gap merging after normalizing overlapping intervals. The converter preserves every neighbor ID and its order, checks inclusion of the original active set, writes all fixed slots and padding, and fully validates the output. M=0 removes only interval metadata/filtering; query alpha continues to fuse both distance spaces. The converter supports other budgets, but M=1/3 are **not** in this queue.

Starling partitions the complete budget-specific topology with its metadata. Its raw partition must cover every node exactly once, agree with its ID-to-page map, and match the expected capacity. To preserve page boundaries, internal holes are filled from final occupied positions before creating a permutation; moved-node counts are archived. All three layouts within a budget use that same permutation for all fields. Neighbor IDs, medoids, PQ codes and returned IDs remain global IDs. The experiment writer applies Starling's order to its own physical group format; it does not reinterpret a native Starling relayout file as the new format. Partitioning is recomputed per budget because topology page capacity changes. Thus original-order budget comparisons isolate compression effects, whereas the reordered budget comparison also includes capacity-adapted Starling partitioning.

Each layout uses the same 8192-byte pages, full fixed records, query-local 16 MiB bounded LRU, up to 128 AIO requests per submission batch, beam=4, K=10, and full retained-candidate exact rerank. Coordinates are streamed in batches of 256 candidate IDs to support high L under the same cache budget. Both original/reordered cases allocate 8N bytes of order/inverse arrays, separate from the equal per-query cache. Per-query aggregate records, topology/coordinate submissions and hits, PQ work, phase times, service latency and RSS are retained. Service latency excludes open-loop queueing. Software submissions are not physical device reads or NAND writes.

The new address mapping and coordinate batching mean older absolute timings are **not** pooled with this batch. Every configuration is measured again in the new harness. Before timing, IDs/distances at L=40/100/200, logical counters and the L=200 search trace must match the previous validated Full-search harness operating on the corresponding budget's identity layout. No cross-budget result equality is expected; equality is required across physical layouts/orders at the same budget/query condition. No-timing binaries pass the same parity check and have identical logical counters.

## Query, high-recall, alpha and instrumentation measurements

The default query matrix is 4 datasets × 3 budgets × 2 orders × 3 layouts × 3 repeats × 2 main threads (1/32): **432 main curves**. L starts at 20/40/60/80/100/120/160/200/300/400. A one-pass screen at 400/600/800/1200/1600 identifies additional levels needed to cover 95%/98% where possible; this batch stops screening at 1600 and reports uncovered targets. All timed points have a separate complete-query-set warmup and at least ten measured seconds. Cyclic replay does not add independent queries. Match recall inside each repeat before aggregation; never extrapolate a missing target.

For the default workload, 4/64-thread diagnostics measure the L points bracketing 90% recall, adding **432 short curves**. These are not full 4/64-thread recall sweeps. Their recall must match the 1-thread points. Default/extra query runs also compare a no-fine-timing build at L=100 to the instrumented curve, with order alternated across repetitions; logical result/page counters must agree. The binary switch removes internal phase clocks, keeping the external wall/service timer and workload counters.

Laion adds the four nondefault supplied alpha pairs on TXY and T|XY in Starling order, all three budgets, T=1/32 and three repeats: **144 additional main curves**. Alpha=0.5 is already the default. Each condition has its own unchanged supplied GT, parity reference and high-recall screen. Cross-alpha recall is not computed against a shared mismatched GT.

The same saved L=200 logical trace is replayed for each measured main configuration/thread, independently of PQ/distance work. Trace throughput is storage replay throughput, not ANN QPS. Device iostat/mpstat and process pidstat are retained for concurrency diagnosis. Fine-clock overhead is reported from the control runs; instrumented performance is not assumed to be overhead-free.

## Single/dual storage controls and patch coalescing

On Full/original order, the TXY and T|XY files also run an equal-byte S-D storage control: X/Y are treated as two contiguous slices of one D-dimensional field, with the same IDs/trace. Submitted pages/bytes must equal the dual-space replay. This is a negative control for generic field grouping, not a new single-space ANN search or a claim about distance equivalence. Separate S-d controls physically omit Y and rebuild [T,X] or [T]|[X], replaying the same logical IDs with only X coordinate requests. Capacity and total bytes differ by design; the result diagnoses byte volume. No single-space graph/GT/semantic recall ranking is produced.

Every default physical layout/repeat runs X-only, Y-only, XY and T field patches with uniform IDs and hot IDs (90% of operations in the first 1% of global IDs). Each mode performs 10,000 operations with identical seeds across layouts, either applying writes individually or coalescing shared pages within batches of 128. Both modes have the same 2 MiB fixed work-buffer allowance and acknowledge only after per-batch fdatasync; the final partial batch is also committed. Coalescing cannot reorder conflicting logical patches. Output includes batch commit p50/p95/p99, amortized cost, software submitted bytes, sync time and throughput. Batch latency is not an individual operation's service/queueing latency.

Before each patch run, touched generated pages are saved outside timing. Entire final pages are compared with the expected last-writer state, then restored, synced and checked byte-for-byte. Incomplete generated layouts are rebuilt on resume. M=0 topology probes change a valid neighbor ID rather than interpreting IDs as nonexistent interval slots. These are single-writer storage probes, **not** graph/PQ-maintaining dynamic ANN updates: there is no WAL, crash-atomicity, concurrent versioning or recovery claim.

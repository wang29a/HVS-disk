# 剪枝修正后的 2M Laion 结果

本轮已结束，状态为 `stopped_at_centre_review_gate`，没有继续构建 α=0.1/0.9 专用图或启动 SSD 路由。24 个计时点验收通过，pending 为零。该停止是预声明的中心工作量／边预算门槛，不表示新剪枝实现未通过语义测试。

统一图构建用时 1,786.6 秒（29.8 分钟），α=0.5 专用图 3,086.8 秒（51.4 分钟）。原 2M 子集、三套穷举 GT、500/500 查询划分均复用。所有查询结果为四线程、NUMA3、精确指针 DRAM 导航、无 PQ／精排、95% Recall@10；配置只在调参集确定，报告集的实测召回夹点内插值。计时为三轮验收均值，不插值尾延迟。

## 中心对照：更多展开，更少计算，延迟下降

| α=0.5 | 统一图 U0 | 固定目标专用图 S |
|---|---:|---:|
| 平均出度 | 33.1325 | 18.6139 |
| 总有向边 | 66,264,979 | 37,227,796 |
| 从共同查询入口可达节点 | 1,998,923 | 1,995,803 |
| L 夹点 | 30/35 | 35/40 |
| 展开节点/查询 | 54.8942 | 66.6780 |
| 精确空间距离评估/查询 | 3,051.99 | 2,752.19 |
| 检查边/查询 | 1,974.16 | 1,703.88 |
| 平均延迟 ms | 0.79397 | 0.73025 |
| QPS | 4,976.37 | 5,408.75 |

专用图少存 43.8% 的边，展开数增加 21.5%，空间距离评估减少 9.8%，平均延迟下降 8.0%，QPS 提升 8.7%。因此展开数不能单独代表搜索成本，也不能因展开量多而称专用图失败。RAM 邻接记录宽度也不同，延迟差不能全部归因于拓扑质量。

预声明门槛要求中心展开比在 [0.8,1.2]、平均度数比在 [0.95,1.05]。实际为 1.2147 和 0.5618，所以暂停两端构图。主要可比性问题是图稀疏度明显不同；同为 R=40 不代表相同实际边预算。这批数是有效的配置比较，但不足以将差异纯粹归因于“统一／专用图结构适配”。下一轮需先冻结如何控制实际边预算／剪枝强度，不能看到结果后静默改参数。

## 统一构图中确实遇到了边界问题

这次修正构图实际执行 52,224,209,904 次优势不等式求解，遇到 1,038,957 次零斜率、23,716,379 次零右端项。原符号分支在同一调用参数下会漏掉正宽度剪枝集合的求解事件有 6,197,830 次。

在同一候选和当前保留见证集上的旧分支旁路统计中，67,992,425 次候选处理的可用区间比修正算法更宽，2,448,584 次达到“旧逻辑会保留、修正逻辑会丢弃”的宽度门槛差异。这些是本次运行的候选处理事件／条件反事实，可能重复涉及同一边，不是旧构图历史次数，也不是旧图净多存的唯一边数。

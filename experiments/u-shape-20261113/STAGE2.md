# U 形诊断：阶段二执行补充

记录日期：2026-11-13。用户确认继续阶段二；原 [协议 v1](PROTOCOL.md) 保留，不覆盖阶段一的历史授权和冻结记录。这里只启动受判断点约束的 DRAM 诊断，SSD 路由尚未实现、尚未排入计时队列。

## 当前已完成什么

2M Laion 随机子集、三套全库穷举 GT 和原有 500/500 查询切分均已完成并复用，没有重算 GT。修正后的欧氏融合构图器已生成统一图，R=40、L_build=200、C=750，8 线程构图约 1,495 秒。图有 2,000,000 节点、66,721,836 条有向边，平均出度 33.3609，Full 使用 8 个区间槽；从查询入口可达 1,999,384 个节点，保留未全连通这一事实。外向 floor/ceil 量化的覆盖核验未发现丢失。

新 `pointer_search.cpp` 直接通过内存指针读邻接记录和原始向量，无页定位、页面缓存、PQ、精排、拓扑提交或坐标提交。精确导航采用 `alpha*sqrt(L2sq_x)+(1-alpha)*sqrt(L2sq_y)`；拼接单空间采用一次完整维度的 L2 内核和一次开方。beam=4、候选维护、入口和终止逻辑与旧实验引擎一致。Full 开/关过滤、No-alpha、拼接单空间四个路径，在真实修正图的 8 条查询及 L=40/120 上，返回 ID、距离和展开批次与旧精确 DRAM 路径逐字节一致，见 [校验记录](validation/pointer-parity.json)。这是功能核验，不是性能结果。

统一图 U0（查询期过滤关闭）的独立报告查询，在 95% Recall@10 得到以下工作量。只对实际召回夹住 95% 的相邻冻结配置做线性插值，不外推。

| α | L 端点 | 实测召回端点 | 展开节点/查询 | 空间距离评估/查询 |
|---|---|---|---:|---:|
| 0.1 | 50 / 55 | 94.66% / 95.12% | 81.77 | 4,297.66 |
| 0.5 | 30 / 35 | 94.80% / 95.30% | 55.91 | 3,083.92 |
| 0.9 | 40 / 60 | 94.14% / 95.56% | 77.14 | 4,122.86 |

两端相对中心的展开数为 1.463×、1.380×，通过预声明的“两端均至少多 10%”判断点。它只说明三点上的偏侧额外工作，不证明连续 U 形，也不说明额外工作一定能由专用图消除。原始文件为远端 `stage2/analysis/u-shape-gate.json`；专用图结果尚未齐全。

## 队列将怎样继续

`build_unified.py` 持全局实验锁，使用已核验的修正构图二进制，生成 source-only 浮点图及 meta，不复制坐标、不生成新 PQ、不创建 SSD 页镜像。`run_stage2.sh` / `stage2_queue.py` 等待统一图后取得同一把锁，任何时刻只有一个正式实验子进程。

队列先补旧 OpenImages 的真正指针 DRAM 对照：双空间 Full 开/关过滤、双空间 No-alpha、等总维度单空间，分别调参并记录 L、展开数、精确距离评估和三轮计时。单空间的训练集在 L=20 已达到 98% 召回，原网格不能夹住 95%，因此没有外推。补充的 `finish_pointer_followups.py` 在主队列之后持同一把锁，仅依据该训练结果扫描 L=10/12/15/20/40，并保留原冻结文件；若 L=10 仍超过 95%，就报告工作点与目标未被夹住，不往 L<10 延伸。这个补充不读取报告结果来决定网格。

Laion 主队列用 U0 完成三点判断，再补统一图开过滤 U1。U0 与固定目标专用图 S 是结构适配的主对照，U1 是独立过滤参照。训练集粗扫后只按训练召回夹点，在区间四等分加密，并预留上下各一个粗档位；随后冻结报告配置。只记录报告集的实际夹点，不按报告延迟挑最优值。

判断点通过后，依次构建 α=0.1、0.5、0.9 专用图。`prepare_specialized.py` 在隔离库中把相同的固定加权欧氏距离写入 HybridIndex 两个内部距离通道，覆盖候选导航、候选排序、质心入口和剪枝的全部 14 个距离调用点，不是只改最后剪枝。构图内部入口允许因固定目标而变化；查询时强制各专用图使用统一图的入口，隔离查询入口的影响。256 节点小图已验证两权重生成不同拓扑、区间均退化为完整 [0,1]、度数不越界，见 [专用构图校验](validation/specialized-validation.json)。该检查不证明图质量或实测收益。

各图保持相同输入顺序与 R/L/C 参数。子集 seed 为 20261113；现有构图器没有暴露独立的构图 seed 接口，多线程构图也不承诺逐字节复现，必须保留实际图哈希。三轮计时复用同一张图，不是三次独立构图。主队列的分阶段计时先保留；所有专用图完成后，后续任务再使用原冻结配置，把同权重的 U0/S/U1 穿插运行三轮（标签 `time-joint-*`），最终方法对比以这组交替计时为准，不拿两个相隔很远的建图时段直接比较延迟。主判断使用展开量和距离评估；RAM 邻接记录仍保留各图的元数据宽度，故延迟还包含记录宽度及访存局部性的影响，不能把延迟差全部归因于图结构。

平均出度相差超过 5% 时标记预算不匹配，不允许进入 SSD 路由。两端展开收益均至少 20%、配对查询重采样区间支持正收益且预算有效，才将状态记为 `dram_complete_ssd_design_ready`。置信区间以已观测的冻结夹点权重为条件，不把它描述成包含所有调参和重建图不确定性的区间。单侧收益或负结果均保留，不自动换参数追求通过。

## 资源与验收

构图 CPU 72–79（8 线程），正式搜索 CPU 72–75（4 线程），内存绑定 NUMA 3，搜索 BLAS 单线程，nice=10、低 I/O 优先级。编译及小型功能检查使用 CPU 80–81，不将它们视为性能测点。计时配置三轮轮换顺序，每点先预热，再测至少 10 秒；仅按时间窗内的外部 CPU、两块 NVMe 写流量和实际 NUMA 策略验收，不按 QPS 高低筛选。每点最多三次，失败记入 `stage2/timings/pending.json` 后继续；语义错误明确停止。未解决的计时缺口不叫“全部完成”。

统一图建图器上限 48 小时、等待它的队列上限 50 小时，全局锁等待上限 6 小时；构图协调进程消失会显式失败。普通搜索进程上限 20 分钟，只停止本队列创建的进程组，不修改其他用户任务。

500 GiB 的实际预留文件是容量保障，不是实验数据。先用已有空闲空间；只有下一张图需要的最小输出余量不足时，才锁定预留元数据并按 GiB 缩小预留文件、记录用途。不会一次释放全部预留，也不会删除旧索引。source-only 图不需要重新占用整份原始向量空间。

## 在 node3 使用

远端目录为 `/mnt/nvme3/wz/hvs-disk-build-20261027/experiments/u-shape-20261113`，数据目录为 `/mnt/nvme2/wz/hvs-u-shape-20261113/subset-2m`。这些脚本依赖已有、经过哈希核验的 `metric-consistent-20261111` 修正库和 `laion-six-cell-20261111` source-only 构图器，不是从任意裸仓库开箱运行的脚本。

仅在尚未启动、或已确认需要从断点恢复时运行；不要在活跃计时期间重编译工具：

```bash
cd /mnt/nvme3/wz/hvs-disk-build-20261027/experiments/u-shape-20261113
python3 scripts/build_tools.py   # 首次准备：编译 + 两组功能核验
tmux new-session -d -s hvs-u-shape-build-20261113 'python3 scripts/build_unified.py'
tmux new-session -d -s hvs-u-shape-queue-20261113 'bash scripts/run_stage2.sh'
# 首次确认主队列已持锁后，再排最终交替计时与低 L 补点：
tmux new-session -d -s hvs-pointer-followups-20261113 'python3 scripts/finish_pointer_followups.py'
```

已经完成的图和验收通过的点可恢复复用；输入、二进制、图或查询切分身份变化会拒绝复用冻结配置。`stage2/build-status.json` 是建图状态，`stage2/queue-status.json` 是主队列状态，`stage2/followup-status.json` 是交替计时与单空间低 L 补点状态；根目录 `status.json` 仍只代表阶段一准备完成。

本地只保存代码、协议与小型核验记录。远端大图、原始日志、冻结参数、逐查询结果与计时验收写入 `stage2/`，不加入 Git。

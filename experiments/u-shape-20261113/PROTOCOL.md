# 统一图偏侧开销诊断协议 v1

冻结日期：2026-11-13。本协议在新图与查询结果产生之前记录；后续若修订，保留版本和原因，不覆盖原约定。本次只启动阶段一的数据准备，不自动启动后三张专用图、完整计时或 SSD 路由实验。

研究问题是：在同一 Laion 子集、精确距离导航和等召回下，统一图在偏侧权重上的额外工作有多少能被专用图消除？它不是为了保证画出 U 形。三点最多支持“中间较低、两侧较高”的观察，不能证明整个权重域的连续 U 形。

## 数据与目标

从 10,642,155 行 Laion 中无放回均匀抽取 2,000,000 行，seed=20261113，抽中的原始 ID 升序排列；两空间共用映射，子集局部 ID 为 0..1,999,999。两空间均为 512 维 float32。保留 `source_ids.bin`、输入大小／mtime／头、输出 SHA256 和逐行核验记录；不把这些信息误称为原始 44 GB 数据的全量内容哈希。

保留原始 1,000 条查询及顺序，直接复制既有 seed=20261111 的 500 调参／500 报告切分。三套 α 文件是 float32 的 0.1、0.5、0.9；GT 以该实际 float32 权重提升到 float64 后，在新子集上穷举，目标为 `α*sqrt(d_x²)+(1-α)*sqrt(d_y²)`，不额外归一化。重复对象及零距离按原任务保留，不擅自排除“自身”；同距离按子集 ID 升序打破平局。

GT 是子集局部 ID 的 top-10，不从全库 GT 截取。保留完整 query 级结果，后续通过原切分读取两组。用小型独立直接距离穷举校验流式 GT，真实 GT 还检查入选候选的独立减法距离、输出 ID 范围和输入身份。输出与分块断点位于 nvme2；代码、协议和日志入口在 nvme3。

## 阶段一判断点：文献

DEG 已有 Oracle 和 Overlay，因此“按权重建专用图／路由”不能算新机制，见 [LITERATURE.md](LITERATURE.md)。继续的理由只限于诊断当前图与 SSD 成本；如果诊断有收益，论文切入点还需证明固定页、缓存、向量共享或存储预算上的具体差异。两周是工作计划，不是运行时间承诺。

## 阶段二之前：统一实验条件

先使用按指针访问邻接表的精确 DRAM 引擎，并核验其融合公式、终止逻辑、候选维护和入口。三个权重共用同一引擎，无 PQ、无精排参数 r、无 Starling、无共享缓存，不把 DRAM 页镜像服务开销当作原生指针遍历。当前页引擎的旧数字不直接混进本表。

主六格为三个权重 × 统一图 U0／专用图 S。U0 保留统一图边集但关闭查询期 alpha 过滤；S 只服务自身 α，不需要区间过滤。这样先测图结构适配损失。统一图开过滤 U1 是独立补充臂，不能用 U1→S 的差距直接归因于拓扑专用化；未补 U1 前也不声称 S 胜过已调好的完整 DEG。

两类构建均用修正后的欧氏目标和区间逻辑，R=40、L_build=200、C=750，保留相同向量、构建输入顺序和 seed。专用图需要在候选导航、候选排序及剪枝中贯彻固定 α。仅把统一 Pareto 候选集的最后剪枝固定到 α，只能叫“剪枝专用化”；若这样测不到收益，不能据此判定查询本身困难或否定完整专用图。

每张图记录实际平均／中位／最大出度、边数、可达性和构建候选数。如果平均边预算相差超过 5%，主结果标注预算不匹配，先做等边预算或每边成本的解释，不能把多存的边当成免费结构收益。L=200 在 Laion 是否导致度数不足属于诊断，不在看到结果后偷偷替换为 400；若统一改参数，另记协议 v2 并重做两臂。

## 阶段二：三点与专用图

先在 2M 统一图上做 α=0.1/0.5/0.9 的精确导航。调参集扫 `L=20,40,60,80,100,120,160,200,300,400,600,800,1200,1600`；只在调参集决定 95% 附近的加密点，记录后冻结，报告集不用于选最低耗时。

三轮交替计时，每点至少 10 秒；主报 95% Recall@10 的展开节点数和精确距离评估，附 L 端点、平均度数、QPS、均值和尾延迟。插值仅在独立报告集实测召回夹住 95% 时进行，不外推，也不插值 p95/p99。展开数是确定性工作量，重复计时不等于三次独立构图；误差分析使用相同查询的配对重采样。

先把两端相对中心的展开数比值各自列出。若两端都不比中心高至少 10%，不自动进入专用图大队列；如怀疑子集尺度影响，只允许提出一次预声明的 4M 复核，确认资源与协议后再执行，不反复换 seed／扩大数据直到出现想要的形状。

专用图完成后计算 `g(α)=1-E_S(α)/E_U0(α)`。至少同时报告两端 g 和中心 g；“中间约 95 次展开”不是预期值，因为它来自旧 PQ 路径。中心专用图有显著收益不自动等于实现错误，可能是全权重结构折中；这时需核对预算、入口和候选质量，区分普遍图质量收益与端点特有收益。

若完整专用图在两端的工作量与 U0 基本相同，停止路由机制开发，只能说“本构建器／预算下未观察到可挽回的专用化收益”，不能证明是查询的固有难度。若收益不足 20%，本轮不进入阶段三；若只有一端超过门槛，标记单侧效应，不宣称对称 U 形。两端均至少 20%、配对置信区间支持正收益且预算有效时，才考虑下一阶段。收益是这套候选机制的实测潜力，不是所有未来算法的理论上限。

## 阶段三：只在通过后进行

以统一图和两端专用图作最简路由基线，不能认领该路由思想为原创。先固定三个权重检验，再在训练查询上决定权重区间的切换点；不能在报告查询上挑路由。比较等召回的 SSD 延迟与拓扑／坐标提交页、两类 I/O 时间和实际缓存占用。

按物理文件和真实驻留预算计费。原始向量与 PQ 可以共享，但应分别记录新拓扑、入口、映射、区间和缓存；统一图自身也要报告同预算配置。DRAM 展开降低不保证 SSD 变快，不先写“问题被放大／解决更便宜”的结论。拿到表格和账本后再决定是否拓展论文目标。

## 当前执行范围与资源

用户已允许阶段一在 node3 两核后台准备。数据准备使用 CPU 76–77、NUMA 3、BLAS/OMP 两线程、nice 15 和低 I/O 优先级，tmux 内持全局队列锁，与已有实验串行；不需要性能空闲窗口。锁等待上限 6 小时、进程外层上限 24 小时，失败保留断点，状态明确记录，不无限等待。

磁盘只写本队列的独立目录，保留至少 2 GiB 余量，不删除历史索引。共享盘当前空间较少，阶段二建图前必须重新做容量预算；不能因为数据准备成功就默认四张图都放得下。既有 DRAM 对照等任务不被本任务取消，也不会因此新增第二条并发计时队列。

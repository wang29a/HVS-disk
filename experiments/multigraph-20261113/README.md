## 用户任务原文

任务：实现并测试 HNSW_M 和 HNSW_Or 两个对比对象的磁盘版本，回答「统一双空间图在各权重下是否有必要、损失在哪里」。

2. 先读 DEG 论文实验部分，记录 DEG 与 HNSW_Or 在各 α 下的对比结论，写进 README。
3. 读取已完成的 OpenImages 双索引离线覆盖率结果，按 α 和实际图像贡献比例分组重新汇总。

【对比对象定义】
- HNSW_M：图像、文本各一张单空间图。各取前 kx、ky 个候选，合并去重，读原始向量按 α·√sx + (1−α)·√sy 精排，返回前 10。三个版本：等量版（kx=ky）；按权重分配版（分配规则只在调参集上确定）；端点版（α≤0.05 或 ≥0.95 时只查主导空间图）。
- HNSW_Or：α=0.1/0.3/0.5/0.7/0.9 各一张专用图。理想版：查询 α 在这五个值上时用对应图；就近版：混合权重负载下用最近的图。
- HNSW_F：只用 α=0.5 专用图回答所有权重。
- 对照：修正后的 DEG 统一图，关过滤和开过滤。

【建图】
- 单空间图：Vamana，R=40，L=200，C=750。写明剪枝松弛系数作用在平方距离还是开方距离上。
- 专用图：修正后的 DEG 构图器，剪枝只按固定 α，参数同上。中心 α=0.5 已有，补 0.1/0.3/0.7/0.9。
- 所有图存为不带区间的紧凑拓扑；坐标文件和两套 PQ 码本共用一份。
- 记录每张图的平均度数、总边数、拓扑字节数、建图时间。

【执行器改动】
1. 以按指针读拓扑的引擎版本为基础，坐标在 DRAM 模式下也改为按指针读，不再整页复制。
2. 支持加载多张图并按查询选图。
3. HNSW_M：两次搜索各用本空间 PQ 导航，默认同一线程先后执行；合并后精排，同一个点的坐标只读一次。
4. 新增计数：每张图的展开数和拓扑页数；HNSW_M 合并前后候选数。

【正确性门槛，全部通过才能计时】
- HNSW_M 在搜索深度很大时，召回接近离线覆盖率上界。
- HNSW_Or 在 α=0.5 的结果与已测的中心专用图一致。
- 同配置下 DRAM 与 SSD 的轨迹和结果逐字节一致。
- 返回距离用 float64 独立重算，最大相对误差 ≤ 5e-6。
任一项不通过：停止，报告原因，不要自行改参数继续。

【测试协议】
- 数据集顺序：先 Laion 200 万子集（α=0.1/0.3/0.5/0.7/0.9，补 0.3/0.7 的穷举 GT）；结果报告后，等确认再做 OpenImages 全量（混合权重，HNSW_Or 只用就近版）。
- 查询切分沿用现有 500 调参 / 500 报告。配置只在调参集按工作量冻结，不看报告集延迟。
- 三条选择规则：页数优先、计算优先、按单页成本加权（拓扑页与坐标页分别计价，单价用已测值）。
- HNSW_M 网格：搜索深度 6–8 档；k ∈ {10,20,40,80,160,320}；分配方式只有等量和按权重两种。
- 运行条件：主条件 PQ+精排、SSD、四线程、NUMA3、无共享缓存；辅助条件拓扑驻留内存、坐标在 SSD。
- 每配置三轮，90% 和 95% Recall@10 处插值后取均值，尾延迟不插值。

【记录指标】
每张图的展开数、PQ 评估数、精排数、拓扑页、坐标页；平均延迟、QPS、p95；各方法拓扑总字节、常驻内存大小、建图时间。

【预先声明的判读】
- HNSW_Or 各权重都明显快于统一图：统一图在每个权重都有损失。
- HNSW_Or 仅两端明显更快、中间接近：损失集中在偏侧权重，支持 U 形来自图。

## 开始前的论文核对

来源为 [DEG v1 §5.1–5.2.2、Appendix E](https://arxiv.org/html/2502.07343v1)。§5.2.2／图6在 OpenImage 上对比 α=0.1、0.3、0.5、0.7、0.9，作者结论是 DEG 与 Oracle 总体性能相近；正文没有提供每个权重的精确差距，不据此虚构逐点数字。在这五个点的逐点记录均为“图6给出曲线、正文未单独量化”；不能推成每一点完全相同。§5.2.1指出固定0.5图在接近0.1时退化，双索引在接近0.5时退化；附录端点0／1的 Oracle 优于 DEG。这些都是作者内存实验，不是本轮 SSD 结论。

## 冻结时明确的实施口径

本轮 HNSW_M／Or／F 是沿用论文的架构标签。按用户指定，实际建图用 Vamana／修正后的固定权重 DEG，不使用原生多层 HNSW；图例必须标注 disk/Vamana-DEG adaptation。统一图关／开过滤也使用新执行器，避免不同代码路径造成对照偏差。保留原统一图与中心专用图的文件和哈希，仅生成派生紧凑格式。统一图过滤需要的完整区间放只读 DRAM 旁表并单列内存、存储成本；不得悄悄丢弃区间或当成免费元数据。

原有中心专用图及本轮固定剪枝沿用已验证的 `<=` 约定；这与论文严格 `<` 不完全相同。Vamana 默认松弛系数1.2，作用于平方 L2：`1.2 * squared_distance(p,q) <= squared_distance(c,q)`；实际编译源码必须核验，若接口不符则停止，不默默更换构图算法。统一与固定双空间目标使用 `α*sqrt(sx)+(1-α)*sqrt(sy)`，不额外归一化。

冻结搜索深度八档为 `[40,80,120,160,240,400,800,1600]`。M 等量版每空间 k；加权版总预算2k，取 `kx=round(2k*w)`、`ky=2k-kx`，w仅从名义α或训练集真邻居的实际贡献均值两条规则选取，不看报告延迟；0<α<1时各至少1。只运行 `max(kx,ky)<=L` 的组合；端点版在非端点等同选定双索引规则，Laion五点不产生端点退化的证据。其余方法使用相同 L 和候选深度 `{10,20,40,80,160,320}` 且候选深度≤L。最近权重平局选较小α，搜索、精排始终使用查询本身的α。

工作量选择三种规则分别最小化总后端页数、维度加权的距离评估工作量，以及 `24.8μs*拓扑页+5.2μs*坐标页`。后两单价来自此前 OpenImages 测量，仅作为冻结的选择启发式，不声称是 Laion 的真实单页成本。每条规则在调参集上冻结一条单调召回前沿；报告集只评价冻结前沿，不挑最低延迟点。无覆盖区间则标未覆盖，不外推。95%主图每条选择规则独立一组，避免按报告结果挑规则。

正确性在小图和真实子集非计时检查中执行。M 的“接近上界”定义为固定 k=320、L=20000 时，与相同查询、相同候选预算的 float64 单空间穷举合并覆盖率相差不超过2个百分点；不通过即停，不加大L或k补救。α=0.5一致性使用同一候选／排序参数与旧指针精确引擎的精确导航模式逐字节比较；PQ路径另做新引擎逐介质一致性。路径一致性比较导航批次、候选ID、精排ID和返回ID／距离字节，剔除时间和物理I/O计数。零距离返回值要求独立重算也为零，不能用人为相对误差分母掩盖错误。

长任务在tmux中与既有实验共用全局锁，构图最多8核、搜索4核、NUMA3，新增GT与离线覆盖穷举2核。只按需释放wz已有预留文件，保留审计，不删除其他数据。等待锁有期限；失败记录status并停止，不自动换参数。实现完成后确认进程入队即可，不持续轮询。Laion完成后停止为 `awaiting_user_review`，没有自动OpenImages阶段。

### 2026-11-13 实施核对 1：Vamana 的实际边界与饱和补边

冻结后的源码核查发现，原生 Index 用 `occlude_factor=max(score/distance)`，跳过 `factor > current_alpha`，而非初稿概括中的 `<=`；系数作用于平方 L2，阶段系数为1、1.2。保留原生实现与 `saturate_graph=true` 的补边行为，不改成单次贪心剪枝。此处纠正比较符描述，避免把新实现冒称为同一算法；图的平均度数和补边配置必须一起报告。已有中心固定图的 LE 语义不变。

### 2026-11-14 实施核对 2：文件入口、相同入口点和运行边界

小图首次检查发现原生 Vamana 输出 `compact.meta`，而通用打包脚本使用 `full.meta` 名称。已在新生成的 Vamana 目录加只读文件别名，未修改原生构图、参数或已有图；失败日志保留。派生紧凑图统一使用已测统一图入口，与此前中心图测量的入口覆盖保持一致；原始图文件、原生入口和指纹均保留。最近图路由对浮点中点使用1e-6的等距容差，平局选择较小权重。

本轮端点优化代码有0／1的小图检查；Laion五个非端点不增加重复计时：`Or_nearest` 与 `Or_ideal` 同图，`M_endpoint` 与所选双索引配置相同，仅作为别名记录。新增GT、训练、正式三轮计时和报告按一个队列串行执行，先等待既有三个复核任务，任一真实数据正确性门槛失败立即停止。小图通过不等于2M真实数据门槛已经通过。

复现入口、停止状态和结果文件见 `RUNBOOK.md`。私有绘图依赖仅装在新实验的 `runtime/python`，不改系统Python。现有OpenImages覆盖率按名义α和GT邻居的实际图像贡献比例重汇总，结果属于256条既有查询的离线覆盖上界，不作为本轮SSD性能数据。

### 2026-11-14 实施核对 3：提前执行双索引覆盖门槛

为避免双索引本身未达上界仍浪费四次专用建图，先用已有中心图检查兼容性，再准备GT并建X／Y图，随即执行原定 `L=20000,k=320` 的双索引上界门槛。通过后才补四张专用图，再完成全部逐介质门槛。门槛参数和2个百分点阈值不变；失败仍立即停止。该调整只提前失败点，不把正确性查询用于调参。

### 2026-11-14 实施核对 4：用三层检查替换精确候选上界门槛

原因：原来的“PQ图搜索召回接近精确单空间候选联集上界”把PQ排序误差和图遍历遗漏混为一项，增加搜索深度不能消除前者。此前α=0.3在16条预定正确性查询上的94.375%／97.5%属于待分解的测量，不再据此判断实现错误。原始失败、参数、日志和计划文件保留，不覆盖成PASS。

本次更改由用户明确同意。对同一2M底库、同一16条预定查询、同一坐标与PQ码本，固定L=20000、每侧k=320，不重新调参，不重建已有图。A为float64精确距离全库top320，B为使用现有PQ编码、查询表和同一ADC算术的全库top320，C为原图搜索器实际保留的top320。双索引按图像、文本分别比较B/C，再合并按查询α精排；覆盖α=0.1／0.3／0.5／0.7／0.9。单空间B/C候选本身不依赖α，因此只计算一次，按权重分别报告它们覆盖真近邻和精排召回的效果，不伪造成五次独立搜索。

统一图也做同样三层：A按精确加权欧氏和取全库top320，B按加权开方PQ距离取全库top320，C分别用统一图关过滤和开过滤，L=20000、候选深度320。所有层使用同一个原始向量精排目标。既报告每层精排召回，也报告A/B、B/C候选重合及逐查询漏失ID；A/B差距仅作为PQ损失测量，不参与门槛。C中记录的PQ分数须与B全库数组中相同ID的分数字节一致，返回距离仍须通过独立float64相对误差≤5e-6检查。

在计算新结果之前冻结B/C通过阈值：每种空间／统一图开关、每个α下，平均候选覆盖率≥99%，任一查询≥95%；合并精排后的B/C Recall@10绝对差≤1个百分点。16条查询共160个GT位置，因此1个百分点最多容许净差1个命中。双索引两侧分别通过，不能靠另一侧平均掩盖。统一图开／关过滤也分别通过。

PQ分数相同可能有合法的边界平局。B按(PQ分数,ID)规范排序；原搜索器不改平局行为。原始ID集合重合率和边界平局数量都必须报告。门槛使用严格低于B第320名分数的候选覆盖，加上最多满足所需名额的等分边界候选；不能用额外平局候选掩盖严格更近候选遗漏。定义为 `(C中严格低于边界的数量 + min(C中边界等分数量, 320-B中严格低于边界数量))/320`。无平局时即普通top320集合覆盖率。

逐查询导出B找到而C漏掉的候选，分别标记图像侧、文本侧及统一图；同时给出漏失候选是否属于当前α的GT top10。所有层的候选均以float64独立精排，使B/C只相差候选获取。另保留原生float精排结果，并核对双索引C在α=0.1／0.3与此前已完成记录一致，防止诊断代码悄悄改变执行路径。

新检查及代码指纹写入 `runtime/three-layer-20261114/`。原 `runtime/plan.json`、原构图和原二进制不改；后续恢复使用独立的追加计划，记录父计划和本次协议指纹，复用既有GT和图的内容哈希。通过后恢复剩余专用图及原有性能队列；任一B/C门槛失败仍立即停止，不自动加大L或k。正确性查询不参与选择性能参数。本次仅跑Laion，不扩展OpenImages。

### 2026-11-14 实施核对 4a：PQ数值一致性的事前细则

尚未运行16条真实诊断查询。隔离小图发现，在现有 `-Ofast` 编译和不同批量长度下，同ID的开方／融合PQ分数不总是逐字节一致，12条小图查询的最大相对差为2.36e-7。这不涉及更换码本、融合目标或搜索参数。为避免把末位浮点差异再混成遍历错误，将第4条的PQ分数字节一致要求细化为：保留位差计数，最大相对误差必须≤5e-6，参考分数为零时仍要求严格为零。B/C候选ID、顺序与原搜索器保持原样；只在比较边界平局时，按全库B对相同ID计算的分数标记C的分数。不能用该标记改变搜索或候选选取。原始C分数的误差审计单列，99%／95%候选覆盖和1个百分点召回门槛均不变。

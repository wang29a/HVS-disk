# Four-dataset concurrency and supplied-alpha experiment

This queue supplements the earlier four-scheme experiments using the unchanged d2a39e2 search libraries and already validated indexes on nvme3. It does not build indexes or calculate new ground truth. An independent C++ measurement driver calls the original `beam_search` and `pq_page_rerank_search` APIs; no repository C++ implementation is modified. The two binaries reuse the exact compile definitions of the separated and baseline builds.

Node3 root: `/mnt/nvme3/wz/hvs-disk-build-20261027/experiments/concurrency-alpha/`. Session: `hvs-concurrency-alpha-20261027`. The launcher is `scripts/run.sh`; `status.json`, `logs/queue.log`, per-run logs and JSON results, and `analysis/summary.json` give progress. The runner has an exclusive lock and resumes completed JSON tasks after verifying settings, supplied inputs, driver and library identities.

The first complete run, OpenImages mixed-alpha baseline with one thread, finished at 19:36:57. Local `bootstrap/` contains the validation report, build identities, input manifest, hardware snapshot and that first run as launch evidence; live progress remains on node3.

All 672 runs and 6,720 measured points finished on 2026-10-28 at 10:16:56 CST. See [RESULTS.md](RESULTS.md) for the completed analysis and limitations. `completed-evidence.tar.gz` archives the complete remote evidence; `raw/` is its local extraction. `analyze_completed.py` regenerates the audit, matched-recall statistics, report and plots from that archive (Python 3 plus Matplotlib). No new ground truth was calculated.

Threads are 1,2,4,8,16,32,64, with beam=4, NUMA nodes 0,1 and memory interleaving across those nodes. There are 48 physical cores in the two nodes, so 64 threads includes SMT. Each configuration tests baseline, Full, Merge-2 and No-alpha, three repetitions with rotated method/thread order. L is 20,40,60,80,100,120,160,200,300,400. All actual index data reads remain on nvme3.

OpenImages, CC3M and HowTo100M retain their original per-query alpha and matching GT. Their alpha values span approximately 0.0011 to 0.9974; these are mixed-alpha workloads, not constant-alpha=0.5. Each measurement additionally reports Recall, latency, native I/O and comparisons in the five alpha buckets [0,.2), [.2,.4), [.4,.6), [.6,.8), [.8,1]. These buckets contain different queries and share a mixed concurrent workload; they are descriptive and must not be called a controlled fixed-alpha QPS experiment.

Laion uses five existing fixed-alpha query/GT pairs: 0.1,0.3,0.5,0.7,0.9. The 0.5 GT under `gt/` is byte-identical to the previously validated default GT. Other pairings are checked for existing alpha values, matrix dimensions and legal GT IDs; their exhaustive nearest neighbors are not recomputed. Missing fixed-alpha GT for the other datasets and alpha endpoints 0/1 are explicitly skipped, not generated or replaced with another alpha's GT.

The queue covers eight dataset/alpha conditions, 672 processes and 6,720 L points. Each timed point runs at least five seconds; low-thread points can take longer because at least the original query set is replayed once. The theoretical measurement lower bound is 9.33 hours, excluding index loading, calibration, failed calibration attempts and other overhead. All four original workloads run before the additional Laion alpha settings.

To avoid the short 1,000-query tail effect, each point uses a single continuous OpenMP loop with enough cyclic replays to reach the requested interval. Every replay has its own output and stats storage, so concurrent replays do not race on query results. Pilot queries and too-short calibration attempts are excluded. This extends measurement time, not the number of distinct statistical queries. Native per-query I/O counters remain implementation-specific and are not physical device-read counters. P95, P99 and P99.9 are computed over all measured invocations with explicit names.

Before the queue, six original-vs-driver cases compare Recall, hops and comparison counts at L=40,100, covering all OpenImages methods, unequal CC3M dimensions and Laion; a duration test checks continuous replay. Driver code is formatted and built with GCC11 against each existing library. Compile commands, hashes and the validation report are archived. Failure stops the queue with a status report; no partial failed task is counted as complete.

`iostat` samples nvme3 once per second, and `pidstat` records each search process's CPU and context switching. Each L record includes its measured interval and start timestamp. Incremental summaries include raw repeat counts, mean/stddev and matched-recall interpolation only for complete three-repeat curves; early best-thread observations are not final scaling conclusions.

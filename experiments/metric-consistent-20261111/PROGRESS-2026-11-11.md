# 新图精确导航对照的阶段结果

更新：本轮队列已完成，321 个计时点全部验收、零待补。六格的完整三轮、L/r、工作量、I/O 分解与运行条件以 [完整报告](STAGE-RESULTS-2026-11-11.md) 为准。下文保留早期检查快照及恢复过程，不能将其中“尚未完成”作为当前状态。

本记录基于 node3 的远端汇总，日期为 2026-11-11。新 OpenImages 双空间图已完成构建及整图独立核验，456,699 个节点、17,110,356 条边、21,951,791 对浮点区间。Full 与 No-alpha 的邻居 ID/顺序、保守区间覆盖及页面 padding 核验均通过。新 Full 实际为 7 槽位、11 节点/页，No-alpha 为 0 槽位、49 节点/页。已有坐标与构图/GT 使用的全部向量值一致，500 查询跨介质轨迹及结果一致性检查通过。

当前完成了精确距离 DRAM 搜索的调参和报告集工作量扫描，三轮正式计时仍在继续。PQ 的 DRAM/SSD 对照和等总维度单空间对照尚未完成。以下计时仅是第一轮，不能当作三轮稳定汇总，也不是生产搜索路径或 SSD 的结果。

设置为同一新图、Full 页、原 ID 顺序、四线程 NUMA 3、精确距离导航、无 PQ/精排、关闭跨查询共享缓存。配置在冻结的 500 条调参查询上确定，下表来自另外 500 条报告查询，计时独立预热后循环回放至少 10 秒。

| 首轮实测点 | 关闭过滤 | 开启过滤 |
|---|---:|---:|
| L | 40 | 60 |
| Recall@10 | 95.24% | 95.18% |
| 平均延迟 | 1.886 ms | 1.485 ms |
| QPS | 2,121 | 2,692 |
| p95（该点实测，不插值） | 2.420 ms | 1.892 ms |
| 每查询两空间距离内核调用总数 | 3,482.984 | 2,728.452 |
| 每查询拓扑页 DRAM 服务数 | 56.644 | 79.512 |

使用已测点夹住 95% Recall@10 做线性插值，关闭/开启过滤分别约为 1.850/1.461 ms、2,180/2,747 QPS。首轮对应平均延迟降低约 21.0%，QPS 提高约 26.0%，距离内核调用减少约 21.6%。拓扑页 DRAM 服务数则从 55.585 增到 78.060，约增加 40.4%。这不是 SSD 物理 I/O，不能写成磁盘读页或磁盘加速结论。90% 召回不在关过滤现有报告点的覆盖内，不向下外推。

这组结果初步说明，在统一距离目标后的新图及精确导航路径上，过滤虽需要更深的搜索并增加拓扑页服务，仍能通过减少精确距离计算获得加速。它支持“alpha 在这条内存路径上有用”的条件性观察。还不能判断其收益是否在 SSD 上更大，也不能判断双空间解耦是否比单空间更困难。新图还同时修正了区间合并和度数上限，不能把相对历史配置的变化单独归因于距离开方。

正式计时曾因监控缺陷停滞。旧监控在进程退出后读取到空 numa_maps，并用这个空状态覆盖存活期间的正确 bind:3 记录，首个计时点因此被反复拒绝。修复时保留了 637 份旧拒绝记录，没有将其追认为正式结果。实机重现确认“存活时 bind:3、退出成僵尸后映射为空”，五项回归覆盖退出、测量窗口外证据、错误 CPU 亲和性及错误内存策略等情况。

新监控只使用计时窗口内的存活进程证据，要求至少三份有效 NUMA 样本。若 NUMA 校验失败就停止，外部干扰最多重试三次；各次恢复使用独立记录名，避免覆盖旧尝试。修复只改变 Python 监控与验收，C++ 搜索二进制、源图、PQ、查询、GT 和冻结配置均保持一致，并保存前后输入清单。恢复后已观察到 12 个计时点通过验收，队列进入第二轮；这是本记录的状态快照，不表示后续阶段已完成。

后续检查已确认精确距离 DRAM 的三轮 33 个计时点全部验收，队列已自动进入 PQ 的 L/r 调参扫描。随后在无子任务的协调器检查点接入了超时、单点待补和有限补跑保护，保留全部已验收数据及已完成调参点。新增 4 项回归验证了失败点不阻挡其余测点、有限补跑、非法配置不被静默跳过、验收点复用以及自有进程组清理。该更新没有改变搜索器、图、查询、GT、PQ 或配置选择规则，前后脚本与输入清单保留在远端 `analysis/queue-reliability-v3.json`。

PQ 调参完成 108 个点后，检查发现确定性诊断也在等待 CPU 空闲。该等待已移除，诊断继续四核低优先级执行，只使用其召回、轨迹和工作量，不使用其计时。第五项队列回归专门验证“非计时诊断不依赖空闲窗口”，与前述测试全部通过。正式计时的 CPU/NUMA/磁盘验收规则保持不变。

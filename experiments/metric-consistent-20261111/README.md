# 统一距离目标后的优先实验

本队列替代旧的未完成原生 DEG 与继续扩展 alpha/布局的任务。旧日志、索引和已完成结果全部保留。旧结果反映旧实现，不能直接作为修正后过滤开关的因果结论。正式实验限定 OpenImages，Laion 复验暂缓。远端根目录为 `/mnt/nvme3/wz/hvs-disk-build-20261027/experiments/metric-consistent-20261111`，tmux 会话为 `hvs-metric-consistent-20261111`。执行状态以远端 `status.json` 为准，本文列出协议，不表示所有阶段均已完成。

新图和精确距离 DRAM 对照的阶段结果及 NUMA 监控修复记录见 [2026-11-11 进展](PROGRESS-2026-11-11.md)。该记录区分首轮计时、工作量扫描与尚未完成的 PQ/SSD/单空间实验，不将历史拒绝点追认为正式结果。

本轮 OpenImages 队列现已完成，321 个计时点全部验收，待补为零。精确距离 DRAM 和 PQ DRAM/SSD 的完整三轮见 [六格完整结果](STAGE-RESULTS-2026-11-11.md)。报告补齐了每格的实际 L/r 端点、展开数、导航/精排距离评估、两类提交页与时间、修复后重建图的身份、统一融合公式和两种调参规则。独立单空间布局任务也已执行完成，其对比结果另行汇总，不混入六格。

队列已加入单点故障隔离。计时进程最长运行 180 秒；外部干扰最多重试三次，再将该点写入 `analysis/pending-measurements.json` 并继续其他点，每阶段结束后有一次补跑机会。未解决的点保留为缺口，最终状态为 `complete_with_pending`，不能写成全部完成。NUMA、参数和数据一致性错误仍会明确报错停止，不接受无效数据。普通子任务最长 20 分钟，建图和拼接资源准备最长 4 小时。只终止该队列创建的子进程组，验收通过的点断点续跑时直接复用。

`progress.json` 记录最近完成的任务、已验收计时点数和待补点数；`status.json` 区分正在运行、等待资源及失败原因，资源等待额外记录已等待秒数。不能仅凭 status 更新时间变化判断有新结果。正式计时在 CPU/磁盘繁忙时仍按原协议等待，不把受干扰测点计入正式结果。召回、轨迹和确定性工作量诊断不等待计时空闲窗口，使用四核、nice 10 直接执行，其耗时不能作为性能证据。队列故障隔离由 5 项控制流、进程退出和非计时进度回归验证，连同 NUMA 监控的 5 项回归均已在 node3 通过。

已完成的距离目标核验是 32 条固定抽样查询、全库 456,699 个向量、float64 穷举。现有 GT 与加权欧氏距离 top-10 的平均重合率为 100%，加权平方 L2 与加权欧氏距离的平均 top-10 重合率为 70.625%。这确认了两个排序目标在实际数据上有明显差别，尚不能单独证明其导致历史过滤性能下降。原始逐查询结果位于 `analysis/objective-audit.json`。样本基础向量及查询的 L2 范数均接近 1；逐向量单位范数不能替代论文所定义的全局距离尺度归一化溯源。

编译、真实距离融合与 128-chunk ADC 回归、区间合并及补集回归已通过。512 节点小图逐边核验了 15,017 条边和 18,371 对浮点区间，邻居 ID/顺序、保守覆盖、空槽与页面 padding 不一致均为零。另在历史图上用 8 条查询做了 8 个分支的功能检查，覆盖 DRAM/SSD 一致性、Full 绕过过滤与紧凑格式一致性、无 PQ/精排的精确导航，以及真正 128-chunk 单向量 ADC。返回距离相对 float64 独立重算的最大相对误差为约 1.21e-7。这些小检查属于功能验证，不属于新图的性能结果。

先穷举扫描 32 条固定抽样查询，核验现有 mixed-alpha GT 的排序目标，并比较加权欧氏距离与加权平方 L2 的 top-10 重合率。计算使用 float64 和全部基础向量，输出每查询列表、GT 重合率和样本向量范数。现有 GT 不重算。若加权欧氏目标与现有 GT 的平均 top-10 重合低于 99%，队列停止在语义核验，不继续构图。

通过上述检查后，双空间构图、精确导航、PQ 导航和精排都对齐 `alpha*sqrt(squared_l2_x)+(1-alpha)*sqrt(squared_l2_y)`。开方发生在每个空间的完整距离求和后。低层平方 L2 内核保持原约定，单空间调用不全局改动。历史构图器还存在遗漏最后一个剪枝区间和层内超过 R 的问题，实验版本一并修正，并保留变换前源码、变换脚本、逐文件哈希及隔离静态库。

DEG §3.1 与 ACTIVE §2.1 定义的是按两个全局尺度归一化后的欧氏距离融合。现有 GT 生成器对存储向量直接计算欧氏距离，未见额外尺度因子。存储向量是否已由预处理完成全局尺度归一化尚未确认，不能用样本向量范数代替该溯源。首轮的任务定义以现有 GT 实际语义为准，运行期不另加归一化，也不宣称完成原论文归一化设定的复现。来源为 [DEG](https://arxiv.org/html/2502.07343v1#S3.SS1) 与 [ACTIVE](https://arxiv.org/html/2610.35751v1#S2.SS1)。

源图重新构建，名义参数为 L=200、R=40、C=750、8 个构图线程。构图时保留浮点区间。写盘对下端点向下取整、上端点向上取整，合并量化后重叠区间，避免缩窄原覆盖；`(0,0)` 是现有 reader 的空槽位，因此单点零区间保守编码为 `[0,1]`。独立核验器逐边检查 Full/No-alpha 的 ID 与顺序、浮点覆盖包含、零槽位、度数、页面 padding 和部分尾页。原截断算法的上界收缩数量另外统计，不和新算法的零收缩结论混用。Full 的 slots 与页密度以新图实际值为准，不假定仍是 6 或 12 节点/页。

构图器输出中的 `old_truncation_shrunk_edges` 指至少一个区间的右端点被旧算法截断缩小的边，`old_truncation_lost_width_pair_sum` 按区间对累计右端缩窄宽度。它们没有扣除同一条边其他区间可能补回的覆盖，不能直接当成整边区间并集的缩窄边数或查询权重损失比例。新编码的逐原始区间包含检查则足以保证原始区间并集不被缩窄。

随后执行同一套候选池、入口、beam=4 和终止逻辑的三级对照。第一层是精确距离导航与 DRAM 供页，没有 PQ 计算或精排。第二层是 PQ 导航与独立深度 r 精排，页面完全载入 DRAM。第三层保持第二层计算不变，仅换成 SSD O_DIRECT/AIO 供页。每层比较 Full 页上过滤开关，先在固定 L=60、r=40 下逐字节验证 DRAM/SSD 返回 ID、距离及遍历轨迹一致。

单空间路径将两个 64-byte 编码交织成一份 128-byte 编码，使用一次 128-chunk ADC；精确距离使用一次完整 1536 维 L2 内核。两份已有的 64-chunk 码本在此构成一个拼接空间乘积量化器，避免把“单空间”实现成两次独立融合或仅重命名双空间任务。搜索器的候选维护和 I/O 服务逻辑仍共用。

查询沿用已冻结的 seed=20261111、500 调参/500 报告划分，先核验各切片哈希。L 扫描 `20,40,60,80,100,120,160,200,300,400,600,800`，PQ 精排深度扫描不大于 L 的 `10,20,40,80,160,320,L`。只在调参查询上选配置，按页数与距离评估量保留预定召回档位的代表，并保存整个不被支配的调参前沿。报告集不参与选择，不能把该选择称为延迟全局最优。报告集先测冻结前沿的工作量和真近邻发现率、C_L 覆盖、C_r 覆盖及最终 Recall@10，再对冻结代表配置三轮交替计时，每点至少 10 秒。90%/95% 的插值必须被报告集实测点夹住；不足时写未覆盖，不按报告结果重新挑参数。

三级实验之后准备一个真正独立构建的 1536 维单空间 Vamana 图。向量是原始 X/Y 的拼接，目标为 `sqrt(squared_l2_x+squared_l2_y)`，使用自身的全量精确 GT；只有这个新目标需要新 GT。再与双空间 No-alpha、双空间 Full 分别比较 TXY 到 T｜XY 的收益变化。三个物理布局均存相同的 1536 个 float，PQ 总字节均为 128；单空间使用两份现有码本作为一个由 128 个 chunk 组成的乘积量化器，ADC 累加后整体开方。此处物理字段仍以 X/Y 两段保存，逻辑上是一个单向量距离，不能将它误称为双目标查询。

判读规则预先固定。若单空间和双空间 No-alpha 的解耦收益接近、Full 不同，优先归因于 alpha 信息及其与布局的交互。若前两者也不同，只能说明差异不能由 alpha 单独解释，还需核对图、工作量和距离代价。若三者接近，就撤回“本任务的解耦必然比单向量更困难”的主张。不开过滤或压缩更快不预设为必然结果。

长任务在 tmux 内持有全局 `queue.lock` 串行执行，NUMA 3 内存绑定，构图最多 8 线程，搜索固定 4 线程，BLAS 搜索阶段 1 线程。使用 CPU 72–79 构图、72–75 搜索，同时检查对应 SMT 兄弟的负载。正式测点记录实际 CPU affinity、VMA NUMA bind 策略、逐秒外部 CPU 负载与 nvme3 读写流量。仅依据外部干扰阈值接受或重测，不根据 QPS 好坏筛结果。DRAM 的页服务计数不称为物理 SSD I/O，拓扑/坐标提交按阶段归属，总后端页数是两阶段之和，不能把耦合页重复相加。

nvme3 空间较少，坐标文件直接只读复用，拼接建图输入写在 `/mnt/nvme2/wz/hvs-metric-consistent-20261111`。每次只生成一个耦合页镜像，完成该臂后保存校验及哈希并回收本队列生成的镜像，保留浮点图、Canonical 拓扑、元信息、结果和重建代码。不会删除其他人的文件或原始历史索引。

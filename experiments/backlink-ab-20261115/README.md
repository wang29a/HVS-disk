# 反向边插入 A/B 对照：冻结协议

任务：按 DEG 原版逻辑实现反向边插入，重建统一图，与当前版本对比，判断反向边处理方式对已有结论（尤其开过滤结论）的影响。

【开始前】
1. 新建实验目录，本说明写入 README 并提交冻结。改动只在末尾追加记录。
2. 停止上一个离线审计（backlink-range-audit），在其 README 末尾注明转为本方案。

【两个版本的定义】
- A（当前版本）：节点 n 选好邻居后，对每个邻居 d：若 d 的邻居数 < R，直接追加 d→n 并复制 n→d 的区间；满了才对 d 的邻居表剪枝。
- B（原版 DEG 方式）：对每个邻居 d，无论是否已满，都把「d 当前的邻居 + n」交给剪枝函数重新剪一次，用结果替换 d 的邻居表。对应原版 DEG 的 Link 函数（src/component_init.cpp）。
两者其余部分完全相同：修正后的剪枝函数（含零斜率修正）、开方后的距离、建图搜索、入口点维护、R=40、L=200、C=750、无归一化。

【实现】
1. 只修改反向边插入函数（inter_insert），新增一个编译开关或参数选择 A/B，A 的行为必须保持不变。
2. B 中剪枝使用邻居表里已存的两个空间距离，不重新计算。对 d 的读改写全程持有 d 的写锁，避免并发下丢失更新。
3. B 不需要建完后的最终清理（因为每次都剪过）；保留原清理代码但记录它是否改动了任何节点。
4. 构图器用正式编译选项，但关闭快速浮点（-fno-fast-math -ffp-contract=off），A 和 B 用同一套选项。记录完整编译选项和源码哈希。

【正确性门槛（全部通过才能建正式图）】
a. 参照比对：从 Laion 抽 1 万条，单线程，分别用 B 和 DEG 作者原版代码建图。原版代码中第二个距离改为第二个向量开方后的 L2，归一化参数设为 1，参数与 B 对齐（max_m=R=40，ef_construction=L=200）。比较两张图：
  - 每个节点邻居集合的一致比例（目标 ≥ 99%）
  - 不一致的节点，列出差异的边和区间，判断是否只来自浮点末位或并列时的顺序
  若一致比例 < 99% 且差异不能解释：停止并报告。
b. 结构检查（A、B 都做）：每个节点度数 ≤ R；无自环；无重复边；所有保存的区间非空且在 [0,1] 内；区间已合并且有序。
c. 回归：A 在 1 万规模下的输出与当前构图器逐边一致，证明 A 没有被改动。

【正式建图】
- 数据：Laion 200 万子集，沿用 U 形实验的查询切分和 GT（α=0.1/0.3/0.5/0.7/0.9）。
- A 建 2 次，B 建 2 次（同参数、八线程、NUMA3），用于估计多线程建图本身的波动。
- 每张图记录：建图时间、平均度数、度数分布、总边数、各 α 下的活动边比例、区间旁表大小。
- 每张图都导出为紧凑拓扑和区间旁表两部分，与现有格式一致。

【测量】
第一阶段：DRAM 工作量（四线程、按指针读拓扑的执行器）
- 每张图，五个权重，开过滤和关过滤。
- 调参只在调参集上，按现有三条规则冻结；报告集上在 95% Recall@10 处插值。
- 指标：展开数、PQ 评估数、95% 召回所需 L、精排数。三轮。

第二阶段：SSD 关键格子（第一阶段完成后）
- 每个版本取一张图（第一次建的），α=0.1 和 0.5，开过滤和关过滤，三轮。
- 指标：平均延迟、QPS、p95、拓扑页、坐标页。

【预先声明的判读】
先用 A 两次建图之间、B 两次建图之间的差异，确定建图波动。以下「明显」指差异 ≥ 10% 且大于建图波动的两倍。
- B 上开过滤仍明显比关过滤慢（SSD）：「过滤不划算」在原版 DEG 图上成立。论文改用 B 作为 DEG 统一图，结论沿用。
- B 上开过滤的劣势明显缩小、或在某些权重转为占优：之前的过滤结论部分来自反向边处理方式，以 B 为准重写过滤相关结论，并扩展到 OpenImages。
- A 关过滤明显快于 B：追加的反向边有助于导航，原版 DEG 剪枝在磁盘上偏严格，进入下一阶段的松弛系数实验。
- A 与 B 各项差异都不明显：反向边处理方式影响很小，论文中说明实现差异，结论沿用。

【交付】
1. 三项正确性门槛的结果。
2. 四张图的统计表（建图时间、度数、活动边比例等）。
3. DRAM 工作量表，按权重和开关过滤，标出建图波动。
4. SSD 关键格子表。
5. 按判读给出结论和建议。

【约束】
- 不修改已有的图和正式构图器的默认行为。
- 第一阶段完成后先汇报，第二阶段是否执行由用户确认。
- 不启动 OpenImages 或全量 Laion 重建。

使用tmux和共用队列flock，等待/超时/重试有界。构图最多八核、DRAM搜索四核、离线处理两核，绑定NUMA3；空间只按需释放自有空白reserve。第一阶段结束后明确标记等待用户确认，不写自动启动SSD/OpenImages/全量Laion的分支。

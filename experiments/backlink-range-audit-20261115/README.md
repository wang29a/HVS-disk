# 反向边复制区间：离线审计冻结协议

任务：离线量化统一图中「反向边直接追加、复制区间」造成的区间错误有多大，判断是否需要重测开过滤的结论。不重建全量图，不跑 SSD 计时。

【开始前】
1. 新建实验目录，本说明写入 README 并提交冻结。改动只在末尾追加记录。
2. 写明本次检查的两张图：Laion 200 万子集修正后的统一图（U0），OpenImages 修正后的统一图。都使用建图器输出的浮点区间版本；磁盘量化后的版本作为第二份对照。

【原理】
剪枝函数只用「已保留的邻居」去计算后续边的区间。所以对一个剪枝函数输出的邻居表，按同样顺序再剪一次，保留的边和区间都应完全不变。
反向边在节点未满 R 时被直接追加、区间从对方复制，这些边重新剪枝后会改变。因此「重新剪枝前后的差异」就是被错误保留或带错误区间的边。

【第 0 步：方法验证，必须先通过】
a. 单元测试：随机构造候选池，跑一次剪枝，再对输出跑一次剪枝，断言边集合与区间完全一致。覆盖距离相等、零斜率、零右端项等边界情况。必须用正式构图的编译选项编译。
b. 来源核对：在 Laion 10 万规模上用同一构图器重建一张小图，并在建图时记录每条边的来源（正向剪枝产生 / 反向直接追加 / 满员时剪枝产生）。对这张小图执行下面第 1 步，确认「重新剪枝后变化的边」几乎全部来自「反向直接追加」。
任一项不通过：停止并报告，不进入后续步骤。

【第 1 步：静态差异（两张图都做）】
对每个节点，取当前邻居表（含两个空间的距离），用修正后的剪枝函数重新剪枝，按原保存顺序。逐边分类：
- 不变
- 区间变窄（重算后的可用权重范围是原来的真子集）
- 区间变宽
- 区间改变但互不包含
- 被删除（重算后可用范围为空）
每条边记录原区间和新区间的总宽度与重叠比例（交集宽度 / 并集宽度）。

汇总：
- 各类边的数量和占比
- 受影响节点的占比
- 按节点度数分组（度数 = R 和度数 < R 分开），比较受影响比例
- 删除受影响边后的平均度数

【第 2 步：对搜索决策的影响（最重要）】
用现有开过滤配置下的搜索轨迹（或用审计工具在报告查询上重放遍历），对每一次「检查一条边是否可走」：
- 分别用原区间和重算区间判断，在查询自身的 α 下是否放行
- 统计决策翻转比例：原来放行、重算后拒绝；原来拒绝、重算后放行
- 按 α 分桶报告（Laion 用 0.1/0.3/0.5/0.7/0.9；OpenImages 用偏侧 [0.05,0.15) 与居中 [0.45,0.55)）
- 同时报告翻转涉及的边，有多少出现在通往最终候选的首次发现路径上

【第 3 步：可选，仅当第 2 步翻转比例 ≥ 2% 时做】
用重新剪枝后的邻居表生成新的区间（不改边集合，只替换区间；另做一版连同删除），在 Laion 子集 DRAM 上跑开过滤的工作量对比（展开数、PQ 评估数、95% 召回所需 L），五个权重。只比较工作量，不做 SSD 计时。

【预先声明的判读】
按第 2 步「访问加权的决策翻转比例」：
- < 2%：影响很小。论文注明实现细节，开过滤结论沿用。
- 2%–10%：中等。执行第 3 步；若工作量变化 ≥ 10%，安排重测开过滤的关键 SSD 格子。
- ≥ 10%：影响大。执行第 3 步，并按修正后的建图逻辑重建统一图，重测全部开过滤结论。
另外：若第 1 步删除边占比 ≥ 10%，单独报告，它说明当前统一图明显比原版 DEG 更密，需在论文中说明。

【交付】
1. 第 0 步两项检查的结果。
2. 第 1 步分类表和按度数分组的对比。
3. 第 2 步按 α 分桶的翻转比例表。
4. 按判读表给出结论和建议。
5. 若做了第 3 步，给出工作量对比。

【约束】
- 不修改已有的图文件；重算结果写到新文件。
- 不跑 SSD 计时。
- 第 2 步结果出来后先停下汇报，第 3 步之后的重测由用户决定。

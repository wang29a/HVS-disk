# 双空间更新：锁与I/O优化验证

本目录对应 `codex/dual-space-update-io-v2`，基于已发布检查点 `3bd0a59b58ccb18cf06fcfc0f27efe33591d6ba1`。旧执行器和E1归档不修改。E1的PQ、exact首轮均已归档，后续重复和消融暂停；本轮不重跑E1，全部验证完成后汇报并等待用户确认。

**PQ 模式 = 新点 exact + 反向重剪 PQ；exact 模式 = 新点 exact + 反向重剪 exact。** 这里的“新点exact”指新点选边剪枝，插入候选搜索仍用两套PQ导航；合并沿用同一reprune-dist选项。两者未满追加、满度重剪。“仅满度节点exact重剪”与exact模式等价，取消重复消融。默认仍为PQ。

`E1-COMPARISON.md` 将首轮五个权重的展开数统一换算为相对检查点0的变化，同时保留平均度数和每批满度重剪前后边数。旧报告相对200万全量R1的增幅仍可追溯，不能替代本页所要求的分母。

`run_baseline.py` 在同一全局实验锁下补测冻结原版：1000点插入的阶段时间、全局degree_mutex_持锁/等锁以及持锁期间读页数，并在同一张180万B图、相同向量和PQ、五权重、500报告查询、四线程、三轮上对比执行器search和原查询Engine。静态比较保留召回与展开数；原Engine为四节点beam与SIMD精排，本执行器为逐节点遍历与double累加精排。固定L的延迟差包含这些实现差异，不能全部归因于页锁；有实测夹点时另比较匹配95%ID召回的延迟。原查询源码通过宏引用，不改写原文件。两者都没有跨查询数据缓存，原Engine复用工作缓冲。

优化仍使用同样的8192字节固定记录和原始剪枝库，距离算术不变。拓扑页先读到私有缓冲，在页锁之外计算候选与剪枝；写入时获取该物理页写锁，检查单调版本，再进行原子入度预留，冲突则重新读页和计算。写锁只覆盖校验、预留、物理写完成及短提交尾部，没有原向量读盘或剪枝。统计互斥仅合并计数器，不覆盖I/O。每次事务最多1024次尝试，持续冲突或不能保护入边时报错，不能通过突破R或丢弃唯一入边继续。

入度为每节点原子计数。每个私有页事务在本地模拟逐行的入度变化，使单线程保边次序与原版相同；净删除在写前CAS预扣，净新增只在写完成后发布。其他事务因此只能看到保守计数，不会把尚未写完的新边当作可消耗的已有入边。失败释放本事务预留，不用旧绝对值覆盖别人的计数。计数在写者静止后与物理拓扑完全一致；独立G1/G3审计重算验证。发布节点后、出边计数完成前，accounted标记让反向写者等待；查询只读已提交的完整记录，初始节点直接标记accounted。全局可达仍不是此机制的保证。

批量读取覆盖插入搜索的同层前沿、新点/精确反向剪枝候选坐标、查询精排坐标。读页按物理页号去重并排序，在同一文件锁域持读锁到读完成，结果进入操作私有缓存；每批最多32页，读锁也只持有当前批次，完成后释放再进入下一批。遍历顺序、剪枝顺序和浮点运算保持原样。文件长度只在加载时检查，追加完成后用原子高水位推进，不再逐读调用fstat。不同物理页的写者不互相等待原向量读盘。

`run_validation.py` 独占原全局队列锁。先在Laion1万节点B图上做100次单线程插入逐位对照，再对PQ/exact各运行原版与优化版1000次固定种子混合操作，验证图、坐标、状态快照及操作序列逐字节一致，同时执行G1的每操作结构审计。定向检查覆盖双写者竞争最后入边、失败回滚、未写完的新增边不提前可用、过期页版本拒绝、追加页和批量读，以及查询与同页覆盖写入交错。G3分别在ASan和TSan下运行PQ与exact各600秒并发查询窗口、1000次总更新；若插桩使更新落后，窗口结束后继续排空更新，分别记录窗口内更新数及含排空的总秒；首32次操作形成双写者突发以增加写者重叠，其余操作按原时间表分布；过期页版本拒绝另由确定性定向检查确认；保留查询区间保守召回oracle，并在写者结束后独立重算入度和结构。新单元、剪枝、测试驱动和Linux reader参与插桩，预编译上游支持库和外部依赖没有全部插桩。

运行状态和原始测量只保留在runtime目录。Linux编译、命令、参数、源文件与二进制哈希随证据保存；没有通过的门槛不得记为成功。不提交向量、GT、PQ码、图、索引、运行轨迹、库或二进制。

首次验证中，TSan的内部死锁检测器因一次持有超过64把读锁而中止，并未产生数据竞争报告。原实现只限制每批I/O请求数，未限制整个预取持锁数；现改为32页批次分别持锁，并加入外层操作锁下96页预取的定向回归。首轮源码、失败栈和两组ASan结果保留在 `runtime/validation/`。最终验证使用 `HVS_OPT_VALIDATION_RUN=validation-v2 HVS_OPT_REFERENCE_RUN=validation python3 run_validation.py`；只复用未改变的冻结原版对照摘要，优化版的逐位一致性、G1、ASan/TSan全部重跑。TSan原检测选项保持启用，以 `runtime/validation-v2/` 为最终结果。

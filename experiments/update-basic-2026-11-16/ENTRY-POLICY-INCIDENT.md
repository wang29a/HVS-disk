# 入口维护方向错误与重新验证

2026-11-16。复核 G2 的入口 ID 时发现：全量/初始 B 的七个入口在旧更新执行器中全部被新插入的近中心点替换。进一步检查已验证 B 变体源码，确认 `UpdateEnterpointSet` 按 `(space2 distance, space1 distance, ID)` 升序排序后逆序扫描，只保留 space1 距离严格增大的节点；它维护的是更远前沿。旧 `DualUpdate::update_entries` 和合并后的重建却使用两个距离更小的支配关系。这是实现错误，违反冻结规范复用构图器入口逻辑的要求。

旧版 G1 的结构检查确实通过，旧 G2 的数字也是真实测量，但不能据此给出符合规范的当前门槛通过结论。已撤回旧 G2/G4 通过声明，并停止正在进行的 ASan G3 子进程。该次 G3 未跑满十分钟，不算通过；不存在 TSan 通过结论。`runtime/g3/entry-policy-stop.json` 记录了停止原因、被核验的自有进程命令和 PID，运行器按 SIGTERM 退出保存失败状态。旧实现原始字节保留在 `runtime/entry-policy-incident/old-implementation/`，其 SHA256 与旧 G2 构建记录一致；旧测量目录不覆盖。

修复采用独立 `entry_frontier.h`，按上游更远前沿的排序、逆序扫描、严格递增条件、零初值和相等距离保留最大 ID 的规则选入口；插入和合并重建共用它。建图器与原图不修改。原始例子 `{ID0:(9,9),ID1:(1,1)}` 必须保留 ID0，旧实现会保留 ID1。额外检查使用含零距离、相等距离和重复坐标的随机候选流，十万个前缀与独立元组参考实现的结果及顺序一致。本地该纯 C++ 检查已通过；新执行器仍须在 node3 重新编译并完成门槛，不能用本地语义测试代替 Linux 运行验证。

重新验证使用 `runtime/g1-entry-parity/`、`runtime/g2-entry-parity/`、`runtime/g3-entry-parity/`。新 G2 使用新的可变图目录 `/mnt/nvme2/wz/hvs-update-basic-2026-11-16/g2-entry-parity/`；同一份不可变全量/初始 B、源 ID 和 GT 经 SHA256 核验后只读复用。原全量图的三轮静态测量可以复用，所有增量插入和增量查询测量重新执行。任一真正门槛失败仍停止后续验证。

G0 与独立剪枝库的语义没有变化，可以沿用。连通性诊断、已有 A/B 图的不可达集合和全库 GT 影响分析均直接读取原始图，不依赖错误的更新入口维护，结论保持有效。没有实施连通性修复，也没有修改默认 PQ 重剪距离。

# 更新门槛：入口语义修正版

本页以 node3 的 `entry-parity` 验证目录为准。入口维护已修正为与已验证 B 构图器一致的更远帕累托前沿；旧版通过结论已撤回，错误、修复与保留证据见 `ENTRY-POLICY-INCIDENT.md`。G0 与独立剪枝语义检查继续沿用。

修正版 G1 在 PQ、exact 两种距离下，各重新完成 591 次插入、309 次删除和 100 次合并。随后另作一次最终合并检查和正常退出快照，不计入上述1,000次随机操作。每种模式有 1,002 条结构审计，最终分配 10,591 个 ID、存活 10,282 个节点。初始 U0 仍为 `{8947}`，没有新增不可达节点或不可达的新插入点；最终不可达存活节点仍只有该初始节点。度数、自环、重复边、无效 ID、合并后指向已删除节点和查询返回已删除节点的检查通过。最终平均度数分别为 22.1283 和 24.9042。

修正版 G2 重新生成两套增量图、重新测量全部增量曲线。全量 B 与初始 B、GT、查询切分不变，经 SHA256 核验后只读复用；全量图既有三轮测量也只读复用。以下为固定 500 条报告查询、同一精确 DRAM 执行器在实测夹点内插值得到的 95% ID Recall@10 平均展开数。每种模式、每个权重均测量三轮；确定性的展开数在三轮中一致。

全部 18 项报告比较都低于 +15% 门槛，因此当前版本 G2 通过；结合当前版本两种距离的 G1，G4 通过。它说明两种重剪距离在这个十万点用例中均可用，不足以决定 E1/E3 中长期质量与更新 I/O 的取舍，默认仍为 PQ。

G3 的修正版已通过 ASan、TSan 两个构建下的完整十分钟测试。两次均使用默认 PQ 重剪，四个查询线程与两个更新线程，共享 CPU72–75、NUMA3；每次完成591次插入、309次删除、100次合并。静态调参确定三个权重均使用L=64、rerank=64；独立报告集的静态召回分别为96.76%、98.56%、97.92%。没有暂停更新来获取GT，也没有切换计分口径。

最低窗口指每个权重按完成顺序连续500次查询的保守ID召回下界，全部高于93%门槛。两次均无崩溃、死锁或sanitizer报错；原始查询数、更新数、召回、滚动窗口最低值、页锁等待总和均已从逐条记录重算并与摘要核对。sanitizer引入的开销不同，查询次数差异不作正式性能比较。查询等待页锁逐条记录；ASan与TSan的平均值分别约为72.67微秒、1,975.99微秒，同样仅作为此压力测试的观测。

两种构建均先通过通用页交错测试、度数40变为2的完整拓扑记录定向交错测试，以及枚举16种可能存活状态的GT区间下界自检。主测试用独立操作日志构造查询期间必然存活与可能存活集合，计算对所有可能时刻都成立的保守召回下界；不改生产查询语义来取得GT。sanitizer覆盖新执行器、剪枝、测试驱动、PQ头文件实例化及实际使用的上游Linux读写实现；其余预编译上游辅助模块与外部库未全量重新插桩，因此不宣称上游整个项目通过了全源码sanitizer审计。

当前独立实验执行器的G1–G4全部通过。默认仍为PQ，没有连通性修复，没有改变上游单空间默认行为，尚未开始E1。按冻结规范第9节，在开始E1前汇报并等待用户确认。

G1 原始证据在 `runtime/g1-entry-parity/`；G2 夹点、内插系数和每轮通过条件在 `runtime/g2-entry-parity/comparisons.json`，编译与基线复用身份在同目录。G3 状态在 `runtime/g3-entry-parity/`。离线可达性及 GT 影响结论独立保存在 `GT-RECALL-IMPACT.md`，没有更改原图或原 GT。

## 入边保护修订的验证状态

新版独立执行器在node3完成G1（PQ、exact各1000次操作及1002次审计）、六项定向保护检查、ASan与TSan各600秒并发回归，并通过180万到185万的反例批次重放。原42个旧节点全部有正入度且入口可达，全图新增零入度为0，不可达数仍为1986。完整源码身份与原始结果见 `runtime/g1-in-degree-protection-v2/`、`runtime/degree-validation/`。前文G2/G4属于入边保护之前的版本；新版质量由已重新启动的正式E1继续测量，不将旧版本的质量结果当成新版实测。

## 1. 目标与范围

### 1.1 目标
在现有双空间统一图索引上，实现**基础的插入和删除**，满足：
- 插入、删除后图结构合法，查询结果正确；
- 图质量接近对同一数据集全量重建的图；
- 更新可以和查询并发进行。

### 1.2 范围内
- 单点插入（批量调用），标记删除，后台批量合并删除。
- 查询路径对删除节点的处理。
- 正确性测试与评估实验。

### 1.3 范围外（本版本不做）
- 持久化日志与崩溃恢复（只在正常退出时写快照）。
- PQ 码本更新。
- 更新后的拓扑页重新排布（Starling 重排）。
- 查询时的区间过滤与区间存储。

## 2. 系统前提

| 项目 | 规定 |
|---|---|
| 图 | DEG 方式构建的统一图。默认使用反向边 A/B 实验确定的版本；A/B 结论出来前使用 B（每次反向插入都重剪）。由参数 `--base-graph` 指定 |
| 区间 | **不存储，不使用**。拓扑记录为紧凑格式（只存邻居 ID）。代码中须断言更新路径不读写任何区间数据 |
| 拓扑 | SSD 上的紧凑拓扑文件，每节点最多 R=40 个邻居，原 ID 顺序，无 Starling 重排 |
| 坐标 | SSD 上的坐标文件，每条记录依次存放两个空间的原始向量 |
| 内存 | 两个空间的 PQ 码；更新所需的小型结构（见第 4 节）。**拓扑不常驻内存** |
| 距离 | 统一目标 `d = α·√s_x + (1−α)·√s_y`；剪枝使用两个空间各自开方后的 L2 距离 |
| 剪枝 | 修正后的 DEG 剪枝（含零斜率、区间合并、严格度数上限三处修正），即构图器当前使用的剪枝函数 |

## 4. 设计规范

### 4.1 新增或沿用的内存结构

| 结构 | 内容 | 来源 |
|---|---|---|
| 删除集合 | 已标记删除的节点 ID | 沿用现有 `deletion_set`，改为可并发访问 |
| 空闲 ID 列表 | 合并后回收的 ID，以及对应的拓扑和坐标位置 | 新增 |
| ID 映射 | 节点 ID → 拓扑位置、坐标位置 | 沿用现有映射 |
| PQ 码 | 两个空间各一份，随插入扩展 | 沿用，扩展为双空间 |
| 入口点集合 | 按到两个空间中心的距离维护的帕累托前沿；两个中心使用建图时的值，不更新 | 新增（建图时已有同样逻辑，复用） |
| 页锁表 | 每个拓扑页一把读写锁 | 沿用现有机制；没有则新增 |

### 4.2 查询路径的修改
1. 搜索过程中**可以经过**删除集合中的节点（展开其邻居）。
2. 精排和返回结果时**跳过**删除集合中的节点。
3. 读取拓扑页时遵守第 4.6 节的一致性机制。
4. 其余行为（导航、精排、计数）与现有执行器完全相同。

### 4.3 插入 `insert(x, y, tag)`

按顺序执行：

1. **分配 ID 与写坐标**
   - 优先从空闲 ID 列表取，否则追加新 ID。
   - 将 `(x, y)` 写入坐标文件的对应位置。
   - 用现有两套码本分别编码，写入两个空间的 PQ 码。

2. **候选搜索**
   - 从入口点集合出发，按帕累托层扩展候选（与构图器 `iterate_to_fixed_point` 的逻辑一致）。
   - 距离使用两个空间的 PQ 估算距离；拓扑页按查询路径读取。
   - 候选列表大小 `L_ins`，默认 200。

3. **读取候选原始向量**
   - 从候选中按帕累托层顺序取前 `C_ins` 个，默认 100。
   - 批量读取它们的坐标记录。

4. **新节点剪枝**
   - 计算新节点到这 `C_ins` 个候选、以及候选之间两两的精确距离（两个空间分别开方）。
   - 调用 DEG 剪枝函数，得到新节点的邻居表，最多 R 个。

5. **写新节点的拓扑记录**，按第 4.6 节的方式写入。

6. **反向边**：对新节点邻居表中的每个邻居 d：
   - 取 d 所在拓扑页的写锁，读出 d 的邻居表。
   - 若新节点已在其中：跳过。
   - 若 d 的邻居数 < R：直接追加新节点。
   - 若 d 的邻居数 = R：对「d 的现有邻居 + 新节点」调用 DEG 剪枝，结果替换 d 的邻居表。剪枝所需距离由参数 `--reprune-dist` 决定：
     - `pq`（默认）：d 用其 PQ 码重构为近似向量，与其他点按 PQ 估算距离；不额外读盘。
     - `exact`：读取 d 及其候选的原始向量，计算精确距离。
   - 写回该页，释放锁。同一页上的多个修改应合并为一次写入。

7. **更新入口点集合**：按到两个中心的距离，判断新节点是否进入帕累托前沿。

8. **设为可见**：以上全部完成后，才允许新节点出现在查询结果中（例如通过一个「已提交」标记位）。

### 4.4 删除 `delete(tag)`

1. 将对应 ID 加入删除集合。立即生效：此后查询不返回该节点。
2. 不立即修改图。

### 4.5 合并删除 `consolidate()`

触发条件：删除集合大小 ≥ 当前节点数 × `--consolidate-ratio`（默认 0.05），或显式调用。

1. 按页顺序扫描拓扑文件。
2. 对每个未删除的节点 p，若其邻居中有已删除节点：
   - 候选 = p 的未删除邻居 ∪ p 的每个已删除邻居的未删除邻居。
   - 调用 DEG 剪枝，距离按 `--reprune-dist` 决定。
   - 用结果替换 p 的邻居表。
3. 按页写回，同一页的修改合并为一次写入。
4. 将已删除节点的 ID、拓扑位置和坐标位置放入空闲列表，并从删除集合移除。
5. 若入口点集合中有被删除的节点，从剩余节点中重新计算帕累托前沿。
6. 合并期间查询和插入可以继续；同一页同时只允许一个修改者。

### 4.6 写入与一致性

- 默认沿用阶段 0 报告中现有代码的写入与一致性机制。
- 若现有机制不能保证查询不读到写了一半的页，改用**异地写入**：修改后的记录写入空闲位置，写完后更新 ID 映射，旧位置回收。此改动须在 README 修订记录中说明。
- 坐标记录只在插入时写一次，写入完成后才设置 ID 映射。

### 4.7 参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--base-graph` | B | 初始图版本 |
| `--L-ins` | 200 | 插入时候选列表大小 |
| `--C-ins` | 100 | 读取原始向量的候选数 |
| `--reprune-dist` | pq | 反向边重剪与合并时的距离：pq / exact |
| `--consolidate-ratio` | 0.05 | 触发合并的删除比例 |
| `--update-threads` | 4 | 更新线程数 |

参数默认值在正式实验开始前冻结，之后不得改动；消融实验按第 7 节显式列出的取值运行。

## 6. 正确性门槛

### G1：结构不变式
在 1 万节点的 Laion 子集上，执行 1000 轮随机操作（插入、删除、合并按 6:3:1 混合），每 100 轮检查：
- 每个节点度数 ≤ R；
- 无自环、无重复边；
- 没有边指向已回收的 ID；
- 合并完成后，没有边指向删除集合中的节点；
- 所有未删除节点都能从入口点集合到达；
- 查询结果中不出现已删除节点。
全部满足才通过。

### G2：增量构建的质量
在 10 万节点的 Laion 子集上：
- 全量建图：10 万节点一次建成。
- 增量建图：先建 9 万，再插入 1 万。
- 两者在 α = 0.1 / 0.5 / 0.9 下，用同一份 GT，比较精确导航 DRAM 下 95% 召回所需的展开数。
- 增量版本相对全量版本的增幅 ≤ 15% 才通过。

### G3：并发
在 1 万节点上，4 个查询线程与 2 个更新线程同时运行 10 分钟。
- 无崩溃、无死锁。
- 在 AddressSanitizer 和 ThreadSanitizer 构建下各运行一次，无报错。
- 查询召回在此期间不低于静态图的 95% 召回目标减 2 个百分点。

### G4：两种重剪距离都可用
`--reprune-dist=pq` 和 `exact` 分别通过 G1 和 G2。

**任一门槛不通过：停止并报告，附反例。**

## 7. 评估实验

### 7.1 数据与 GT
- 数据：Laion 200 万子集。
- 每个检查点重新计算 GT：只在当前存活的点上做 float64 全库穷举，按现有方式融合权重。
- 查询：沿用 500 条调参 / 500 条报告的切分；权重 α = 0.1 / 0.3 / 0.5 / 0.7 / 0.9。

### 7.2 参照图
- R1：用全部 200 万点全量构建的图（已有）。
- R2：用删除后剩余的 180 万点全量构建的图（新建，用于 E2）。

### 7.3 实验

**E1 只插入**
- 从 180 万点全量建图开始，分 4 批插入剩余 20 万点，每批 5 万。
- 每批后测量：各权重 95% 召回所需的搜索深度与展开数（DRAM 工作量），以及 SSD 平均延迟。
- 最终状态与 R1 比较。

**E2 只删除**
- 从 R1 开始，随机删除 10%（20 万点），执行合并。
- 合并前、合并后各测量一次，与 R2 比较。

**E3 混合**
- 从 R1 开始，执行 10 轮，每轮插入 1%、删除 1%，每轮结束执行合并。
- 每轮后测量，观察图质量是否随轮数下降。

### 7.4 更新代价
在 E1 和 E2 中同时记录：
- 每次插入的平均延迟、p95；读页数、写页数（拓扑和坐标分开）。
- 插入吞吐，更新线程数为 1 / 4 / 8。
- 合并的耗时、读页数、写页数。
- 更新进行期间的查询延迟与吞吐（4 个查询线程）。

### 7.5 消融
仅在 E1 上，每次只改一个参数：
- `--reprune-dist`：pq / exact
- `--C-ins`：50 / 100

### 7.6 预先声明的判读
以「95% 召回所需展开数相对参照图的增幅」为主指标：
- E1 最终状态和 E2 合并后，五个权重的增幅均 ≤ 10%：基础更新方案可用，作为系统的一部分写入论文。
- 有权重增幅在 10% 到 25% 之间：可用但需说明，报告受影响的权重。
- 有权重增幅 > 25%：图质量不可接受，停止并报告，不进行后续实验。
- E3 中若增幅随轮数持续上升（10 轮后比第 1 轮高 10 个百分点以上），单独报告。
- `pq` 与 `exact` 的增幅相差 ≤ 3 个百分点：默认使用 `pq`；否则报告两者的质量与代价取舍。

## 修订记录 1（2026-11-16，依据阶段 0 评估报告）

原因：阶段 0 发现分离式原地更新与查询之间没有共同的页锁，现有删除集合按 tag 存储且无查询快照，ID 不复用，剪枝接口为单标量距离，本地默认构图器缺少已验证的修正。以下修订替代原规范中对应条款。

1. 一致性（替代 4.6）：使用统一页级读写锁，键为（文件标识，物理页号）。查询读页持读锁，覆盖到读完成并复制到查询私有缓冲区；更新读改写持写锁，覆盖到写完成。查询不使用跨查询共享缓存。异地写入列为后续工作，本版本不实现。须记录查询等待页锁的时间。
2. ID 与位置（替代 4.1 空闲 ID 列表、4.3 第 1 步、4.5 第 4 步）：本版本不复用节点 ID，不复用拓扑和坐标位置。插入一律追加。合并删除只修改图，不回收空间。回收只在离线压缩时进行，本版本不实现。
3. 删除标记（替代 4.1 删除集合、4.4）：按节点 ID 的位图，加载时按最大容量预分配，原子读写。tag 到 ID 的映射另行维护。合并开始时冻结删除集合快照，合并期间的新删除计入下一轮。
4. 容量：PQ 码（两个空间）、ID 映射、删除位图、已提交位图在加载时按 --max-points 预分配，插入过程中不扩容。默认 --max-points = 1.5 × 初始节点数。
5. 已提交标记（替代 4.3 第 8 步）：新增已提交位图。新节点在坐标、两套 PQ 码、拓扑记录、全部反向边写完后才置位。查询遇到未提交节点不展开、不返回。
6. 合并与插入（替代 4.5 第 6 步）：合并期间暂停插入，查询照常进行。

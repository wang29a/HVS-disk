# 双空间更新：正确性检查点（2026-11-17）

这一版保存已在node3编译和验证的独立双空间更新执行器。实现、测试和实验驱动位于 `implementation/`，设计原文及批准修订位于 `README.md`。本提交不改变上游单空间更新默认行为，也不包含工作区已有的构图器修改或论文修改。当前不是性能优化版；E1的PQ和exact首轮已完成归档，后续重复与消融按用户安排暂停，优先进行[独立性能核验](../update-perf-audit-2026-11-17/README.md)。

执行器以紧凑B图为起点，拓扑与原始双空间向量放在SSD，两套PQ码、ID映射、删除及提交状态按容量预留。ID和物理位置只追加，不复用。所有8192字节页的读改写使用统一页读写锁，查询持有操作私有镜像。反向边未满追加、满度重剪，默认PQ距离，exact作为对照；新点出边使用原始向量选边。新增节点在完整写入后才提交。删除先标记，合并冻结删除快照并暂停插入，查询继续；不回收空间。

唯一入边保护确保更新不会把已有正入度的存活节点变成零入度，同时保持R=40。它不保证全局可达，入口BFS不可达数是观测项。为先保证并发正确性，当前入度互斥覆盖反向重剪与物理写完成，exact路径的向量读取和剪枝计算也在其中；缩小锁范围属于后续独立性能版本，尚未实现。

对应当前核心源码，G1在PQ和exact下各执行1000次混合操作，每种1002次独立结构审计通过；六项入边保护定向检查通过。ASan、TSan各完成600秒、1000次更新的并发回归，分别完成70391与6979次查询。插桩范围为新执行器、剪枝、测试驱动与Linux reader，并不覆盖全部预编译上游支持库和外部依赖。180万到185万节点的重放通过，原42个反例点均可达且入度为1。

在线PQ编码与上游批量BLAS编码可能在质心边界上产生不同码，已发现的3字节差异有独立距离诊断和完整在线重编码证明。初始码严格对照冻结批量码，新增码严格对照独立执行的上游在线编码器；搜索始终使用更新快照里的实际码。参考编码仅用于审计，不注入更新路径，不改变GT或ID召回口径。

`evidence/e1/progress-snapshot.json` 保留首次提交时的历史快照。随后PQ和exact首轮均完成全部20万插入，各检查点无新增零入度，不可达存活数保持1986。最终平均度数分别为27.5103和29.2946；95% ID召回下，精确导航展开数相对全量R1的最大增幅分别为22.645%和6.787%。[首轮汇总](../update-perf-audit-2026-11-17/E1-FIRST-PAIR.md)另列PQ的上升趋势及GT理论上限损失。三轮主对照和消融尚未全部完成；本目录 `E1-RESULTS.md` 保留首次提交时的进度快照，不是最终结论。根目录其他报告包括历史失败记录，其阶段性状态以各自时间和本页说明区分。旧版G2/G4结果不作为入边保护后版本的完整质量验收。

这个检查点尚未接入仓库默认CMake构建。node3驱动脚本依赖既有的上游静态库、已验证B图、数据、PQ码本和实验工具；固定远端路径不是通用部署接口。复用环境见 `implementation/run_g0.py` 中的 `HOST_ROOT`、`SOURCE`、`BUILD` 及 `ENV`，编译的完整命令、选项、上游库与二进制哈希见 `evidence/g1/build-identity.json` 和 `evidence/e1/build-identity.json`。从新克隆不能直接运行这些环境专用实验脚本。

源码与已通过Linux构建的身份可以直接核对：`evidence/g1/build-identity.json` 的 `sources` 使用相对文件名，位于 `implementation/` 下；`evidence/large-replay/build-identity.json` 与 `evidence/e1/build-identity.json` 补充大图驱动身份。剪枝的来源与转换说明在 `analysis/prune-provenance.json`。所有新增编译单元要求保留最后的 `-fno-fast-math -ffp-contract=off`。本地macOS不替代Linux构建验证，提交前以这些已完成的node3构建及其精确源码哈希为依据，不抢占正在进行的E1实验重新构建。

纯逻辑检查可在 `implementation/` 下执行 `python3 -m unittest test_quality_metrics test_e1_metrics`。独立入度保护和入口前沿检查可分别用C++17编译 `in_degree_guard_check.cpp`（加 `-pthread`）和 `entry_frontier_check.cpp`。这两项不依赖数据，不能替代上述完整Linux执行器验证。

Git只保存源码、规范、报告和 `evidence/` 中精选的验证记录，清单与校验和见 `evidence/manifest.json`。`runtime/`、图、向量、PQ数据、二进制和大体积逐查询轨迹不随本提交保存。报告中原有的 `runtime/...` 引用对应完整本地或远端归档；精选证据的原始路径在清单中保留。正常退出快照目前用于审计和派生查询文件，不提供快照恢复加载、日志或崩溃恢复，也没有做空间回收、去重和全图连通性修复。

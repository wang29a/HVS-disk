## 已实现的实验代码

`implementation/update_store.h/.cpp` 通过上游 `LinuxAlignedFileReader` 的直接 AIO 接口读写完整 8192 字节页，页锁以拓扑/坐标文件身份和物理页号区分。查询读锁覆盖读入私有缓冲，修改者写锁覆盖读改写及写完成；统计包括页锁等待纳秒和两类文件的读写页数。新追加页先完整清零，不读取 EOF 之外的页。执行器只使用查询/操作私有页镜像，并以页版本防止追加后继续使用同页的旧私有镜像，没有跨查询共享缓存。

`implementation/dual_update.h/.cpp` 包含固定容量双空间 PQ 码、恒等 ID→位置映射、tag→ID 映射、删除位图和已提交位图。默认容量为初始节点数的 1.5 倍；ID、拓扑和坐标位置只追加。代码包括帕累托候选搜索、候选原向量读取、DEG 新点选边、按页合并的反向边写入、未满追加/已满重剪默认策略及每次重剪选项。坐标、两套 PQ、拓扑、反向边完成后才发布已提交标记。删除按 ID 标记；合并冻结删除快照并暂停插入，修复旁路邻居但不回收空间；中心保持建图时的值，入口按中心距离维护，包含正常退出快照写出入口。

这些功能代码已编译，尚未执行双空间插入/删除/合并的 G1 混合操作；不能用上游单空间测试替代它们的验证。并发更新、与既有静态执行器的轨迹/计数等价、快照加载恢复、G2 图质量及 G3 双 sanitizer 压力测试均未验收。没有运行正式性能测量。

## G0 与剪枝来源

`runtime/g0-attempt2/status.json` 为 `G0_PASSED`。骨架页锁用例验证了同页读写交错下完整旧/新页、私有旧镜像不变、不同文件同页号不互相占锁、追加末页补零、容量边界及位图快照。上游 `test_insert_search.cpp` 在 128 个初始单空间向量上完成 8 次插入，更新后 8 条查询的 Recall@10 为 100%。这是小数据读写用例，不能作为双空间更新质量或性能结论。

测试源未改动，但采用测试专用的 `dynamic_index.h` 声明将 reader strategy 显式选为 5。原因是原驱动没有 strategy 命令行参数；strategy=0 不打开分离文件，而当前单空间 rerank 路由还无条件读取第二码本和选择表。夹具使用相同的两个单空间码本和全零选择表，实际仍走同一个向量空间。生产头文件、默认库和默认策略未修改。首次 strategy=1 的失败及 gdb 回溯保留于 `runtime/g0/`；配置完整后的成功记录位于 `runtime/g0-attempt2/`，没有覆盖失败记录。

`implementation/extract_prune.py` 从已验证 B 变体提取独立的“候选池 + 双距离提供器”选边库，保留严格度数上限、零斜率/零右端项、末区间合并及开方 L2 语义。它不再依赖全量向量数组或实验统计注册表；区间只在选边内部临时使用。`runtime/prune-gate/semantic-replay.log` 记录 10000/10000 条实际反向插入候选池逐位一致，比较包括邻居 ID、顺序、两空间源距离、层号及所有临时区间端点。来源与提取转换见 `analysis/prune-provenance.json`。提取的核心源码哈希与本轮执行器构建记录一致。

新执行器翻译单元编译选项末尾追加了 `-fno-fast-math -ffp-contract=off`。上游静态库作为未修改的既有读写层依赖复用，没有宣称全库重新编译。完整命令、环境、源码和二进制 SHA256 位于各阶段的 `build-identity.json` 与编译 JSON；当前执行器身份以 `runtime/g1/build-identity.json` 为准。

## G1 初始图反例

测试采用既有 Laion 1 万子集的 B 图和原 ID 顺序紧凑布局，在本轮目录创建可写副本。初始 PQ 码按同一份子集原 ID 从既有 2M PQ 文件提取。建图中心按原构图器的输入 ID 顺序进行 float32 顺序累加和 float32 除法重建，之后不更新；具体输入身份在 `runtime/g1/pq/fixture-identity.json`。

初始图 10000 个节点中仅 9999 个可从入口集合到达。不可达节点为局部 ID **8947**，对应原 2M 子集 ID **1789839**；它的出度为 1，仅有边 `8947 → 118`，入度为 0，且不在 10 个入口之中。因此，从当前入口集合无法到达它。`runtime/g1/pq/operations.jsonl` 为零行，插入、删除、合并均未开始；这不是本轮更新导致的退化。

独立 Python 审计直接读取未修改的原始 B 浮点图和紧凑图，确认全图每个节点的有序邻接表完全相同，BFS 复现同一个不可达节点。新执行器得到的反例与此独立读取一致。原始图、捕获图、紧凑图及实验副本哈希，以及完整入口集合、出边、入边和原始 ID 映射，均保存在 `analysis/baseline-counterexample.json`。

这里没有把“既有 B 图”视为自动满足全部 G1 不变式，也没有静默放宽可达性条件、删除该节点、把它临时加入入口或修改原图。G1 为未通过，G2/G3/G4 为未运行。停止位置见 `runtime/g1/status.json`。

## 下一步需要的设计决定

当前规范没有提供图连通性修复规则，而严格 G1 要求所有存活节点都可达。需要明确是否允许在实验副本中增加连通性修复阶段，再继续原定 1000 次操作。针对本反例，最小候选修改是在节点 118 的邻居表追加 8947：118 当前出度为 1，追加后为 2，仍小于 R=40，且 118 位于已可达部分。这个修改尚未执行；它只能解决此例，不能自动证明后续插入、重剪和合并均保持连通，也不能免除重新运行 G1–G4。若采用该方向，需要把一般修复策略及其测量范围写入后续规范修订，保留原始 B 图作为对照。

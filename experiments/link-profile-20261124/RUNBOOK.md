# Laion 200 万配对构建计时

Link 与子图构建固定 node3 的 NUMA0、8 个物理核 16–23。续跑的合并使用 NUMA2、8 个物理核 48–55。SSD 固定 NUMA3、4 个物理核 72–75。同核超线程从 Linux 拓扑读取。每次计时前对物理核和它们的同核超线程分别采样 5 秒，任一组平均占用超过 10% 就等待。开始后每 5 秒采样同核超线程，任一采样窗口超过 10% 视为受干扰。保留日志和采样，剔除该次时长并在同一配置下重跑。5 秒窗口末尾的残余时段若达到 1 秒也计入。以同一全局实验锁隔离本项目的计时作业。SSD 对照期间不运行拓扑重排计时。

R=26 公平对照先用原 K=8 双侧扩边的 351,039 点分片复测，再用原旧双路 503,134 点分片复测。两个分片均固定 R=26、L=200、C=750、同一计时二进制。对照同时报告 Link 墙钟和每插入点微秒。R 从 40 降到 26 的影响以 K=8 的同一分片作前后比较。固定 R 的两个分片仍有不同的点数和候选分布。

原片内扫描中 K=8 的 L=200/C=400 与 L=128/C=750 计时受同核超线程干扰，保留作废记录。冻结构建路径不读取 C，直接沿用干净的 L=200/C=750 与 L=128/C=400 两点，不重跑 C 组合。因此，L=128 仍有一组已验证的片内读数。

整图沿用原 K=8 双侧扩边的八个成员列表。按点度数版在子图内对单分片点使用 R=40，对出现在多个分片的点使用 R=27。新点剪枝、反向维护和最终清理均按被写行的度数上限执行。合并算法和合并后上限 R=40 沿用原版。L 缩短版只把片内 L 从 200 调为 128，R 固定 40。固定上限做逐字节校验，混合上限的小图逐行校验；整图分单分片和多分片报告平均度数。构建耗时以分片提取、建子图和合并的有效计时之和报告。

SSD 同批复制两张新图、原 K=8 和一次性全量图到 NVMe3，使用同一 Starling 节点顺序、Merge-2、原生开方搜索、PQ、真实查询和 GT。预检后静置 10 分钟，按 α=0.9 至 0.1 倒序运行，每个 L 下交替测量，轮间轮换首图，共三轮。每轮按 ID Recall@10 内插 95% 延迟，分别记录拓扑页、坐标页。只有三轮均能内插时报告配对相对延迟。

### 合并续跑

按点设 R 的八个子图已通过 NUMA0 计时检查。进入合并前，NUMA0 空闲内存低于 46 GiB，构建保护在合并进程启动前停止。保存全部子图、原计时及停止日志。两张新图的合并统一改绑 NUMA2 物理核 48–55 和本地内存，继续沿用同核超线程采样与内存保护。L=128 的子图仍在 NUMA0 的原物理核构建。原 K=8 的合并时间是 NUMA0 历史记录，涉及历史合并时间的对比同时标注绑核。
